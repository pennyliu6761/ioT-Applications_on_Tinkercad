## 學習地圖

### 你已經會的（上週動手課）
- ✅ 電阻的作用：限制電流，保護 LED 不被燒毀
- ✅ 三顆 LED 串聯：電流相同、每顆分到的電壓不同、其中一顆壞掉整條線都不亮
- ✅ 三顆 LED 並聯：每顆電壓相同、電流依各自需求分配、其中一顆壞掉不影響其他顆

### 這週要新學的
| 觀念 | 說明 | 為什麼工業上重要 |
|---|---|---|
| `pinMode()` | 告訴 Arduino「這隻腳要做輸入還是輸出」 | 每個 PLC / 控制器都有輸入輸出腳位設定 |
| `digitalWrite()` | 讓腳位輸出高電位（5V）或低電位（0V） | 控制繼電器、指示燈、電磁閥的開關 |
| `delay()` | 讓程式暫停指定的毫秒數 | 模擬機台動作的節拍時間 |
| `int` 變數 | 用有意義的名字取代數字腳位 | 提升程式碼可讀性，這是業界基本規範 |
| `for` 迴圈 | 讓重複的動作用一行程式碼完成 | 控制產線上大量相同單元（感測器陣列、燈號牆） |
| 陣列（Array） | 把多個相關數值放在同一個變數裡 | 管理多站點、多設備的資料 |
| `Serial.println()` | 把資料印到電腦螢幕上 | 相當於工業控制的「監控台」，除錯必備工具 |

### 使用平台
全程使用 [Tinkercad Circuits](https://www.tinkercad.com/)，程式編輯視窗請切換為「**文字模式（Text）**」，不要用積木模式。

## 電路體檢站（3 分鐘快速複習）

在動手寫程式前，先花 3 分鐘做個小體檢，確認你對上週的電路觀念還記得清楚。**這不是新教材，是體檢**，如果你都能秒答，代表可以放心往下走。

**體檢題 1**：三顆 LED 串聯，如果拔掉其中一顆，其他兩顆會怎樣？
> 答案：全部熄滅。因為串聯電路只有一條路徑，斷了就沒有電流通過。

**體檢題 2**：三顆 LED 並聯，如果拔掉其中一顆，其他兩顆會怎樣？
> 答案：不受影響，繼續正常發光。因為並聯電路每一條支路是獨立的。

**體檢題 3**：為什麼 LED 一定要串一顆電阻，不能直接接電源？
> 答案：LED 本身內阻很小，沒有限流會瞬間通過過大電流而燒毀。電阻負責把多餘的電壓「吃掉」，讓通過 LED 的電流落在安全範圍（通常是 15~20mA）。

**體檢題 4**：如果你有 5 顆 LED，想要「各自獨立控制開關」（就是這週要做的），你應該用串聯還是並聯的接法？
> 答案：並聯（各自獨立一條迴路），因為程式需要能個別控制每一顆燈的腳位。這週的所有電路，本質上都是「多組並聯迴路」，只是每一組各自接到 Arduino 不同的腳位。

如果以上 4 題你都答對了，代表你已經具備這週所需要的所有電路基礎知識，接下來我們把重心完全放在「程式邏輯」上。

## 模擬設計專案配置

> 本週電路會分成 5 個階段逐步擴充，越後面關卡會用到越多顆 LED。建議直接把最大陣容（8 顆 LED）一次接好，之後每個關卡只是「用不同數量的腳位」，不需要重新接線。

### 元件清單
| 元件 | 數量 | 說明 |
|---|---|---|
| Arduino Uno R3 | 1 | 主控板 |
| Breadboard（麵包板） | 1 | 電路佈局 |
| LED（建議紅、黃、綠各挑幾顆做視覺區分） | 8 | 機關指示燈 |
| 220Ω 電阻 | 8 | 每顆 LED 各配一顆 |

### 接線步驟
1. 將麵包板放在工作區，Arduino Uno 放在旁邊。
2. 在麵包板上，由左至右依序插入 8 顆 LED，每顆之間留一點間距方便辨識。
3. 每顆 LED 的**長腳（正極）**各自串接一顆 220Ω 電阻。
4. 8 顆電阻的另一端，分別用導線接到 Arduino 的 **Pin 2, 3, 4, 5, 6, 7, 8, 9**（依序對應第 1~8 顆燈）。
5. 8 顆 LED 的**短腳（負極）**，全部用導線接到麵包板的藍色負極軌（-）。
6. 麵包板負極軌用一條線接回 Arduino 的 **GND**。

### 腳位對照表（本週共用）
| LED 編號 | 腳位 | 建議顏色 |
|---|---|---|
| LED 1 | Pin 2 | 紅 |
| LED 2 | Pin 3 | 紅 |
| LED 3 | Pin 4 | 黃 |
| LED 4 | Pin 5 | 黃 |
| LED 5 | Pin 6 | 綠 |
| LED 6 | Pin 7 | 綠 |
| LED 7 | Pin 8 | 任意色 |
| LED 8 | Pin 9 | 任意色 |

> 💡 **配置檢查清單**：開始寫程式前，請對照下表逐一勾選，養成「先驗證硬體、再寫邏輯」的工程習慣。
> - [ ] 8 顆 LED 都有各自的電阻
> - [ ] 8 顆 LED 的負極都接到同一條負極軌
> - [ ] 負極軌已經接回 Arduino GND
> - [ ] 8 條正極端的導線分別接到 Pin 2~9，且沒有重複或空接

## 後端程式設計：五道機關關卡

### 關卡 1：通電測試 — 認識 setup() 與 loop()

**機關故事**：密室的第一道燈必須先確認「電路真的通了」，這是任何專案開發的第一步——**先讓最簡單的東西動起來，再逐步疊加複雜度**。

#### 範例 1-1：單顆 LED 基礎閃爍
```cpp
// ============================================
// 範例 1-1：機關通電測試 - 最基本的閃爍
// ============================================

int pinLed = 2;   // 用變數儲存腳位編號，往後修改腳位只需改這一行

void setup() {
  // setup() 只會在開機時執行「一次」，適合放初始化設定
  pinMode(pinLed, OUTPUT);   // 宣告 Pin 2 為輸出腳位
}

void loop() {
  // loop() 會「無限重複」執行，適合放需要持續進行的動作
  digitalWrite(pinLed, HIGH);  // 機關通電：LED 亮起
  delay(500);                  // 維持 500 毫秒
  digitalWrite(pinLed, LOW);   // 機關斷電：LED 熄滅
  delay(500);
}
```
**思考問題**：如果把兩個 `delay(500)` 都改成 `delay(2000)`，機關會變成什麼樣子？為什麼 `pinMode()` 只需要寫一次，卻要放在 `setup()` 裡？

#### 範例 1-2：全部 8 顆燈同時測試
```cpp
// ============================================
// 範例 1-2：一次驗證 8 顆 LED 是否都正常
// 工程概念：批次測試比一顆一顆測試有效率很多
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};  // 陣列：把 8 個腳位放在同一個變數裡
int numLeds = 8;                           // 陣列長度

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);   // 用迴圈依序設定每個腳位為輸出，不用寫 8 次 pinMode
  }
}

void loop() {
  for (int i = 0; i < numLeds; i++) {
    digitalWrite(ledPins[i], HIGH);  // 全部同時點亮
  }
  delay(1000);

  for (int i = 0; i < numLeds; i++) {
    digitalWrite(ledPins[i], LOW);   // 全部同時熄滅
  }
  delay(1000);
}
```
**教學重點**：這裡第一次出現「陣列 + for 迴圈」的組合，這是整學期最重要的程式技巧之一——**只要元件數量增加，迴圈可以讓程式碼長度幾乎不變**。試著想像一下，如果沒有用迴圈，8 顆燈的全亮全滅需要寫幾行程式碼？

### 關卡 2：雙燈機關 — 變數與交替邏輯

**機關故事**：密室裡有一道「雙向感應門」，兩盞燈必須交替閃爍，代表「左側通道開啟」與「右側通道開啟」輪流出現，玩家要抓準時機在正確的燈亮起時通過。

#### 範例 2-1：兩顆燈交替閃爍
```cpp
// ============================================
// 範例 2-1：雙向感應門 - 交替閃爍
// ============================================

int pinLeft = 2;
int pinRight = 3;

void setup() {
  pinMode(pinLeft, OUTPUT);
  pinMode(pinRight, OUTPUT);
}

void loop() {
  digitalWrite(pinLeft, HIGH);   // 左側通道開啟
  digitalWrite(pinRight, LOW);
  delay(600);

  digitalWrite(pinLeft, LOW);
  digitalWrite(pinRight, HIGH);  // 右側通道開啟
  delay(600);
}
```

#### 範例 2-2：三段式紅綠燈邏輯（機關警示燈）
```cpp
// ============================================
// 範例 2-2：機關運作中的警示號誌（紅、黃、綠三段）
// 靈感來源：真實十字路口紅綠燈的運作邏輯
// ============================================

int pinRed = 4;
int pinYellow = 5;
int pinGreen = 6;

void setup() {
  pinMode(pinRed, OUTPUT);
  pinMode(pinYellow, OUTPUT);
  pinMode(pinGreen, OUTPUT);
}

void loop() {
  digitalWrite(pinGreen, HIGH);   // 綠燈：機關安全，可通行
  delay(2000);
  digitalWrite(pinGreen, LOW);

  digitalWrite(pinYellow, HIGH);  // 黃燈：機關即將啟動，準備離開
  delay(500);
  digitalWrite(pinYellow, LOW);

  digitalWrite(pinRed, HIGH);     // 紅燈：機關啟動中，禁止通行
  delay(2000);
  digitalWrite(pinRed, LOW);
}
```

#### 範例 2-3：用變數控制節奏快慢（可調式機關）
```cpp
// ============================================
// 範例 2-3：把節奏時間存成變數，之後只要改一個地方就能調整全部速度
// 工程概念：把「會變動的數字」獨立成變數，是良好的程式設計習慣
// ============================================

int pinLeft = 2;
int pinRight = 3;
int stepTime = 300;   // 統一控制節奏快慢的變數

void setup() {
  pinMode(pinLeft, OUTPUT);
  pinMode(pinRight, OUTPUT);
}

void loop() {
  digitalWrite(pinLeft, HIGH);
  digitalWrite(pinRight, LOW);
  delay(stepTime);

  digitalWrite(pinLeft, LOW);
  digitalWrite(pinRight, HIGH);
  delay(stepTime);
}
```
**思考問題**：範例 2-3 把 `stepTime` 設成 300，如果要讓機關「越來越快」，你會怎麼修改程式碼？（提示：這個問題會在關卡 5 得到解答）

### 關卡 3：三色密碼鎖 — 陣列與序列圖樣

**機關故事**：密室金庫上有 3 顆指示燈（紅、黃、綠），會依照一組固定的「序列」依序亮起，玩家必須觀察並記下正確的順序，才能在另一個機關（實體轉盤，非本課程範圍）輸入正確答案。

#### 範例 3-1：固定序列播放
```cpp
// ============================================
// 範例 3-1：金庫密碼提示燈 - 依序播放固定序列
// 序列：紅 → 黃 → 綠 → 紅 → 紅（重複末位代表密碼的一部分）
// ============================================

int pinRed = 4;
int pinYellow = 5;
int pinGreen = 6;

void lightPin(int pin) {
  digitalWrite(pin, HIGH);
  delay(400);
  digitalWrite(pin, LOW);
  delay(200);   // 每個燈之間留一點空白間隔，避免玩家看混
}

void setup() {
  pinMode(pinRed, OUTPUT);
  pinMode(pinYellow, OUTPUT);
  pinMode(pinGreen, OUTPUT);
}

void loop() {
  lightPin(pinRed);
  lightPin(pinYellow);
  lightPin(pinGreen);
  lightPin(pinRed);
  lightPin(pinRed);

  delay(1500);   // 一輪播放完，暫停久一點再重播，給玩家記錄的時間
}
```
**教學重點**：這裡把「點亮一顆燈再熄滅」的重複動作，封裝成一個自訂函式 `lightPin()`。這是這學期第一次接觸「自訂函式」，往後只要呼叫 `lightPin(某個腳位)`，就不用每次都重寫 `digitalWrite` + `delay` 四行程式碼。

#### 範例 3-2：用陣列儲存序列，讓密碼更容易修改
```cpp
// ============================================
// 範例 3-2：把密碼序列存成陣列，修改密碼只需改一行資料
// ============================================

int pinRed = 4;
int pinYellow = 5;
int pinGreen = 6;

// 用陣列儲存這次要播放的密碼序列（腳位順序）
int sequence[] = {pinRed, pinYellow, pinGreen, pinRed, pinRed};
int sequenceLength = 5;

void lightPin(int pin) {
  digitalWrite(pin, HIGH);
  delay(400);
  digitalWrite(pin, LOW);
  delay(200);
}

void setup() {
  pinMode(pinRed, OUTPUT);
  pinMode(pinYellow, OUTPUT);
  pinMode(pinGreen, OUTPUT);
}

void loop() {
  for (int i = 0; i < sequenceLength; i++) {
    lightPin(sequence[i]);   // 依序讀取陣列裡的每個腳位並點亮
  }
  delay(1500);
}
```
**思考問題**：如果要把密碼改成「綠→綠→紅→黃」，範例 3-1 跟範例 3-2 哪一種寫法修改起來比較輕鬆？為什麼？

#### 範例 3-3：兩組不同密碼交替出題（進階版遊戲機關）
```cpp
// ============================================
// 範例 3-3：機關會交替出兩種不同的密碼題目，增加遊戲變化性
// ============================================

int pinRed = 4;
int pinYellow = 5;
int pinGreen = 6;

int sequenceA[] = {pinRed, pinGreen, pinYellow};
int sequenceB[] = {pinGreen, pinGreen, pinRed, pinYellow};

void lightPin(int pin) {
  digitalWrite(pin, HIGH);
  delay(400);
  digitalWrite(pin, LOW);
  delay(200);
}

void playSequence(int seq[], int length) {
  // 這是一個「帶參數」的函式，可以傳入不同的陣列與長度
  for (int i = 0; i < length; i++) {
    lightPin(seq[i]);
  }
}

void setup() {
  pinMode(pinRed, OUTPUT);
  pinMode(pinYellow, OUTPUT);
  pinMode(pinGreen, OUTPUT);
}

void loop() {
  playSequence(sequenceA, 3);
  delay(1500);
  playSequence(sequenceB, 4);
  delay(1500);
}
```

### 關卡 4：光跡索敵 — for 迴圈與來回掃描

**機關故事**：密室天花板架設了一整排感應燈條，模擬電影中常見的「雷射掃描巡邏」效果，玩家必須計算掃描的節奏，抓準空檔通過。

#### 範例 4-1：單向依序點亮（跑馬燈）
```cpp
// ============================================
// 範例 4-1：光跡索敵 - 由左至右依序掃描
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};
int numLeds = 8;

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
}

void loop() {
  for (int i = 0; i < numLeds; i++) {
    digitalWrite(ledPins[i], HIGH);
    delay(100);
    digitalWrite(ledPins[i], LOW);
  }
}
```

#### 範例 4-2：來回掃描（經典霹靂燈 / Knight Rider 效果）
```cpp
// ============================================
// 範例 4-2：來回掃描 - 由左到右，再由右到左
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};
int numLeds = 8;

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
}

void loop() {
  // 由左到右
  for (int i = 0; i < numLeds; i++) {
    digitalWrite(ledPins[i], HIGH);
    delay(80);
    digitalWrite(ledPins[i], LOW);
  }
  // 由右到左（注意起始位置避免最後一顆被重複點亮兩次）
  for (int i = numLeds - 2; i >= 0; i--) {
    digitalWrite(ledPins[i], HIGH);
    delay(80);
    digitalWrite(ledPins[i], LOW);
  }
}
```
**思考問題**：為什麼由右到左的迴圈要從 `numLeds - 2` 開始，而不是 `numLeds - 1`？如果改成 `numLeds - 1` 開始，畫面會有什麼變化（提示：某一顆燈會連續亮兩次）？

#### 範例 4-3：雙尾巴掃描效果（進階視覺特效）
```cpp
// ============================================
// 範例 4-3：兩顆燈同時往中間靠攏，製造「雙向索敵」的視覺效果
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};
int numLeds = 8;

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
}

void loop() {
  int left = 0;
  int right = numLeds - 1;

  // 只要左指標還沒超過右指標，就持續往中間移動
  while (left <= right) {
    digitalWrite(ledPins[left], HIGH);
    digitalWrite(ledPins[right], HIGH);
    delay(150);
    digitalWrite(ledPins[left], LOW);
    digitalWrite(ledPins[right], LOW);

    left = left + 1;    // 左指標往右移動
    right = right - 1;  // 右指標往左移動
  }
}
```
**新語法提醒**：這裡第一次出現 `while` 迴圈，跟 `for` 迴圈的差別在於：`while` 不需要事先知道要跑幾次，只要條件（`left <= right`）成立就會持續執行。

#### 範例 4-4：隨機索敵燈（不規則掃描，增加緊張感）
```cpp
// ============================================
// 範例 4-4：隨機挑選一顆燈點亮，模擬不規則的巡邏感應燈
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};
int numLeds = 8;

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
}

void loop() {
  int randomIndex = random(0, numLeds);   // random(下限, 上限) 會回傳「下限 <= x < 上限」的隨機整數
  digitalWrite(ledPins[randomIndex], HIGH);
  delay(150);
  digitalWrite(ledPins[randomIndex], LOW);
  delay(50);
}
```
**教學提醒**：`random(0, numLeds)` 的範圍是 0 到 numLeds-1（不包含 numLeds 本身），這跟陣列索引「從 0 開始、最大到長度減 1」剛好吻合，這不是巧合，而是刻意設計配合陣列使用。

#### 範例 5-2：倒數計時搭配 LED 閃爍
```cpp
// ============================================
// 範例 5-2：倒數 10 秒，同時 LED 跟著閃爍提示
// ============================================

int pinLed = 9;

void setup() {
  pinMode(pinLed, OUTPUT);
```

#### 範例 5-3：加速倒數（越接近 0 閃爍越快）
```cpp
// ============================================
// 範例 5-3：模擬「時間越少、警示越急促」的緊張感
// 呼應關卡 2 留下的思考問題：如何讓節奏隨時間變化？
// ============================================

int pinLed = 9;

void setup() {
  pinMode(pinLed, OUTPUT);
  Serial.begin(9600);
}

void loop() {
  for (int countdown = 10; countdown >= 1; countdown--) {
    Serial.print("倒數：");
    Serial.println(countdown);

    // 用 map() 把倒數秒數轉換成閃爍間隔：秒數越小，間隔越短（閃越快）
    int blinkDelay = map(countdown, 10, 1, 500, 80);

    digitalWrite(pinLed, HIGH);
    delay(blinkDelay);
    digitalWrite(pinLed, LOW);
    delay(blinkDelay);
  }

  Serial.println("時間到！大門開啟！");
  delay(3000);
}
```
**教學重點**：這裡雖然還沒正式教過 `map()`（第 4 週才會深入介紹），但先讓大家看過一次效果，建立「數值可以互相轉換」的直覺，之後正式學到會更容易理解。

### 🏆 BOSS 關：終極開門序列

**機關故事**：把這一週學到的所有技巧整合起來——密室大門開啟前，必須先播放三色密碼序列，接著進行光跡掃描巡邏，最後倒數 5 秒開門。這是本週的總驗收關卡。

```cpp
// ============================================
// BOSS 關：終極開門序列 - 整合本週所有技巧
// 流程：① 播放密碼序列 → ② 光跡掃描 → ③ 倒數開門
// ============================================

int ledPins[] = {2, 3, 4, 5, 6, 7, 8, 9};
int numLeds = 8;

int pinRed = 2;
int pinYellow = 4;
int pinGreen = 6;

int codeSequence[] = {pinRed, pinGreen, pinYellow, pinRed};
int codeLength = 4;

// --- 自訂函式區 ---

void lightPin(int pin, int duration) {
  digitalWrite(pin, HIGH);
  delay(duration);
  digitalWrite(pin, LOW);
  delay(150);
}

void playCodeSequence() {
  Serial.println(">>> 階段一：播放密碼序列 <<<");
  for (int i = 0; i < codeLength; i++) {
    lightPin(codeSequence[i], 400);
  }
}

void scanSweep() {
  Serial.println(">>> 階段二：光跡掃描巡邏 <<<");
  for (int i = 0; i < numLeds; i++) {
    digitalWrite(ledPins[i], HIGH);
    delay(60);
    digitalWrite(ledPins[i], LOW);
  }
  for (int i = numLeds - 2; i >= 0; i--) {
    digitalWrite(ledPins[i], HIGH);
    delay(60);
    digitalWrite(ledPins[i], LOW);
  }
}

void countdownOpen() {
  Serial.println(">>> 階段三：倒數開門 <<<");
  for (int countdown = 5; countdown >= 1; countdown--) {
    Serial.println(countdown);
    for (int i = 0; i < numLeds; i++) {
      digitalWrite(ledPins[i], HIGH);
    }
    delay(300);
    for (int i = 0; i < numLeds; i++) {
      digitalWrite(ledPins[i], LOW);
    }
    delay(300);
  }
  Serial.println("*** 大門開啟！恭喜通過第一道機關！ ***");
}

// --- 主程式 ---

void setup() {
  for (int i = 0; i < numLeds; i++) {
    pinMode(ledPins[i], OUTPUT);
  }
  Serial.begin(9600);
}

void loop() {
  playCodeSequence();
  delay(500);
  scanSweep();
  delay(500);
  countdownOpen();
  delay(4000);   // 整個流程結束後暫停，模擬「玩家離開、下一組玩家進場」
}
```
**教學重點**：這段程式碼刻意把每個階段都寫成獨立的函式（`playCodeSequence()`、`scanSweep()`、`countdownOpen()`），讓 `loop()` 讀起來就像「劇本大綱」一樣清楚。這種「把複雜邏輯拆成小函式」的寫法，稱為**模組化設計**，是往後每一週、甚至整個學期期末專題都會用到的核心技巧。

## 常見錯誤除錯站

| 現象 | 可能原因 | 解決方式 |
|---|---|---|
| 上傳後所有 LED 都不亮 | `pinMode()` 忘記設定，或設定成 `INPUT` | 檢查 `setup()` 內每個腳位是否都有 `pinMode(pin, OUTPUT)` |
| 部分 LED 不亮 | 該顆 LED 腳位編號打錯，或麵包板該排插孔沒插好 | 對照腳位對照表逐一核對 `ledPins[]` 陣列內容與實際接線 |
| 迴圈跑法怪怪的、燈光跳來跳去 | `for` 迴圈的起始值、結束條件寫錯 | 手動在紙上模擬 `i` 從多少跑到多少，逐一列出每次迴圈 `i` 的值 |
| 程式碼編譯出現 `expected ';'` | 少打分號 | 檢查錯誤訊息指出的行數「上一行」結尾 |
| 陣列存取出現異常（部分燈亂跳） | 陣列索引超出範圍（例如陣列只有 8 個元素卻寫 `ledPins[8]`） | 記得陣列索引從 0 開始，8 個元素的合法索引是 0~7 |
| `random()` 每次結果都一樣 | Tinkercad 模擬環境偶爾種子固定，屬正常現象 | 可忽略，或改用 `randomSeed(millis())` 增加變化（進階選修） |

## 練習題大補帖

### 🟢 基礎題（人人都要會）
1. 修改範例 1-1，讓 LED「亮 200 毫秒、暗 800 毫秒」，做出「短亮長暗」的效果。
2. 修改範例 2-2 的紅綠燈，把黃燈時間從 500 毫秒改成 1000 毫秒。
3. 在範例 1-2 的基礎上，把 8 顆燈的全亮時間從 1000 毫秒改為 300 毫秒，觀察差異。
4. 寫一個程式，讓 3 顆 LED（自選腳位）依序「一顆一顆亮起後全部保持亮著」，最後全部一起熄滅。
5. 修改範例 4-1，把跑馬燈的方向反過來（從右邊開始往左）。

### 🟡 中等題（多數人可以挑戰）
6. 做出「雙向對稱跑馬燈」：燈光從中間往兩側同時擴散，到達最外側後再收回中間，如此反覆。
7. 修改範例 3-2 的密碼陣列，自己設計一組全新的 5 個燈號密碼，並確認程式正確播放。
8. 寫一個程式，讓 8 顆燈分成「前 4 顆」與「後 4 顆」兩組，各自用不同的節奏閃爍（提示：可以用兩個獨立的 `for` 迴圈邏輯，或參考範例 4-3 的雙指標寫法稍作修改）。
9. 在範例 5-2 的倒數程式中，新增一個功能：倒數到 5 秒以內時，額外印出 "警告：時間所剩不多！" 的文字提示。
10. 設計一個「隨機密碼產生器」：每次執行時，用 `random()` 從三種顏色的腳位中隨機挑 4 個組成新的密碼序列並播放（提示：可參考範例 4-4 的 `random()` 用法，並想想陣列要如何動態填入隨機選出的值）。

### 🔴 挑戰題（進階自我挑戰）
11. **速度漸變跑馬燈**：讓範例 4-2 的來回掃描速度隨時間「越來越快」，最後又「越來越慢」，做出一個完整的加速減速循環（提示：需要一個變數控制 `delay()` 的數值，並在每一輪迴圈中遞增或遞減它，注意數值不能減到 0 或負數）。
12. **雙密碼交錯播放進階版**：延伸範例 3-3，讓程式改成透過 `random()` 「隨機」決定這一輪要播放密碼 A 還是密碼 B，而不是固定交替播放。
13. **函式化重構挑戰**：把範例 4-2（來回掃描）改寫成一個獨立函式 `knightRider(int times)`，可以指定要來回掃描幾次，並在 `loop()` 中呼叫這個函式。
14. **多層次警報燈牆**：設計一個情境——8 顆燈平時第 1~2 顆慢速呼吸般交替亮滅，一旦透過程式邏輯設定的「條件」達成（例如某個計數器變數累加到 20），就切換成全部 8 顆燈的高速警報閃爍模式，並在 Serial Monitor 印出「警報已觸發」。這一題會用到本週還沒教的「條件累加判斷」，鼓勵大家先自行嘗試組合已學過的迴圈與變數技巧。
15. **完全自訂機關**：不參考任何範例，自己設計一個「你認為最酷的密室燈光機關」，至少要用到：1 個自訂函式、1 個陣列、1 個迴圈。並寫一小段文字（3-4 句話）說明你的機關情境設定與運作邏輯。

## 反思與延伸討論

1. 這一週我們完全沒有改變任何一條電路接線，只靠「換程式碼」就做出了 15 種以上完全不同的效果。請討論：**在真實工廠自動化系統中，這種「硬體固定、軟體決定行為」的特性，帶來什麼樣的商業價值？**（提示：可以想想設備維護成本、產線彈性、升級方便性等角度）
2. `for` 迴圈跟直接複製貼上 8 次 `digitalWrite`，最終跑出來的「結果」是一樣的，但工程師幾乎都選擇用迴圈寫法。除了「省打字時間」之外，你能想到其他至少兩個理由嗎？
3. BOSS 關程式碼把邏輯拆成三個函式（`playCodeSequence`、`scanSweep`、`countdownOpen`）。如果全部擠在同一個 `loop()` 裡面寫成一長串程式碼，會對「除錯」和「團隊合作開發」造成什麼影響？

第 2 週我們會替密室加上「玩家可以互動」的元件——**按鈕**。這一週所有的機關都是「自動播放」，玩家只能看不能動；有了按鈕之後，玩家才能真正「按下按鍵、觸發機關、參與遊戲」。我們也會遇到這學期第一個經典的硬體 bug——「按鍵彈跳（Bouncing）」，並學會如何用程式解決它。
