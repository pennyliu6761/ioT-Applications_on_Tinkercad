## 學習地圖

### 你已經會的（第 1～4 週）
- ✅ 數位/類比輸出入：`digitalWrite`、`digitalRead`、`analogWrite`、`analogRead`
- ✅ 陣列、迴圈、帶參數的自訂函式
- ✅ `map()` 數值轉換與 `constrain()` 邊界限制
- ✅ 狀態變數、防彈跳、多模式切換

### 這週要新學的
| 觀念 | 說明 | 為什麼工業上重要 |
|---|---|---|
| `tone()` / `noTone()` | 讓蜂鳴器發出（或停止）特定頻率的聲音 | 設備警報、提示音、聽覺化狀態指示的標準做法 |
| 頻率（Frequency） | 決定聲音的「音調高低」，單位赫茲（Hz） | 不同頻率代表不同緊急程度或設備狀態 |
| 光敏電阻（LDR） | 隨環境光線強弱改變電阻值的元件 | 自動照明、入侵偵測、光學計數器的核心元件 |
| 分壓電路（Voltage Divider） | 用兩個電阻串聯，依比例切分電壓 | 幾乎所有類比感測器讀取電路的基本原理 |
| 「遮斷偵測」邏輯 | 偵測數值從「未遮蔽」變成「遮蔽」的瞬間 | 光學計數器、防盜感應、產線通過計數的共通手法 |

## 電路體檢站（3 分鐘快速複習）

**體檢題 1**：上週學過可變電阻是靠「轉動角度改變分壓比例」來產生連續數值。光敏電阻的原理其實類似，只是它是靠「光線強弱改變自身電阻值」，兩者都要搭配另一顆固定電阻組成分壓電路，才能讓 Arduino 讀到有意義的類比數值。這正是善用了上學期「串聯電路電壓會依電阻比例分配」的觀念。

**體檢題 2**：LED 需要限流電阻，可變電阻不需要額外電阻，那光敏電阻呢？
> 答案：光敏電阻**需要**額外搭配一顆固定電阻（通常是 10kΩ）組成分壓電路，原理跟可變電阻的三隻腳不同——光敏電阻本身只有兩隻腳，必須額外用一顆電阻協助分壓，才能把「電阻值變化」轉換成「電壓變化」讓 Arduino 讀取。

**體檢題 3**：蜂鳴器需要接電阻保護嗎？
> 答案：Tinkercad 模擬環境中的蜂鳴器不需要額外電阻，直接接上訊號腳位與 GND 即可運作，這跟 LED 必須加電阻的情況不同（現實中不同型號蜂鳴器規格略有差異，但這學期先以模擬環境的簡化接法為主）。

## 模擬設計專案配置

### 元件清單
| 元件 | 數量 | 說明 |
|---|---|---|
| Arduino Uno R3 | 1 | 主控板 |
| Breadboard | 1 | 電路佈局 |
| Buzzer（蜂鳴器） | 1 | 警報發聲器 |
| Photoresistor（光敏電阻, LDR） | 1 | 雷射網感應器 |
| 10kΩ 電阻 | 1 | LDR 分壓電阻 |
| RGB LED（共陰極） | 1 | 警示燈（沿用第 3 週接法） |
| 220Ω 電阻 | 3 | RGB 三色限流電阻 |

### 接線步驟

**Part A：蜂鳴器**
1. 拖曳一顆 **Buzzer** 到麵包板，正極（通常標示 `+` 或較長腳）接到 Arduino **Pin 8**，負極接負極軌回 GND。

**Part B：光敏電阻（分壓電路）**
1. 拖曳一顆 **Photoresistor** 到麵包板，一腳接 **5V**。
2. 另一腳同時連接兩個地方：
   - 接一顆 **10kΩ 電阻**到 GND
   - 接一條線到 Arduino 的 **A1**（類比輸入腳）
3. 這樣就完成了分壓電路：光線越亮，光敏電阻阻值越小，A1 讀到的電壓越接近 5V（數值越大）；光線越暗，讀到的數值越小。

### 分壓電路原理圖解（文字版）
```
       5V
        │
     光敏電阻（LDR）
        │
        ├──────── 接到 Arduino A1（訊號線）
        │
     10kΩ 電阻
        │
       GND
```
這張圖跟第 2 週的下拉電阻電路長得幾乎一樣，只是把「按鈕」換成了「光敏電阻」——按鈕是「數位開關」（只有通/不通兩種狀態），光敏電阻是「類比可變電阻」（會依光線連續變化阻值），但**電路的分壓原理完全相同**。

**Part C：RGB LED（沿用第 3 週）**
1. R → ~9、G → ~10、B → ~11，各自串接 220Ω 電阻，共同負極接 GND。

### 腳位對照表（本週共用）
| 元件 | 腳位 |
|---|---|
| 蜂鳴器 | Pin 8 |
| 光敏電阻（LDR） | A1 |
| RGB LED - R / G / B | ~9 / ~10 / ~11 |

> 💡 **配置檢查清單**
> - [ ] 蜂鳴器正極接 Pin 8，負極接 GND
> - [ ] 光敏電阻與 10kΩ 電阻組成分壓電路，訊號線接 A1
> - [ ] RGB LED 三色腳接在 PWM 腳位（~9、~10、~11）

## 後端程式設計：五道機關關卡

### 關卡 1：蜂鳴器發聲 — 認識 tone() 與 noTone()

**機關故事**：在設計複雜的警報系統前，你得先確認蜂鳴器真的能發出聲音。

#### 範例 1-1：發出單一頻率聲音
```cpp
// ============================================
// 範例 1-1：讓蜂鳴器發出固定頻率的聲音
// ============================================

int pinBuzzer = 8;

void setup() {
}

void loop() {
  tone(pinBuzzer, 1000);   // 發出 1000Hz 的聲音（數字越大音調越高）
  delay(500);
  noTone(pinBuzzer);       // 停止發聲
  delay(500);
}
```

#### 範例 1-2：測試不同頻率的音調高低
```cpp
// ============================================
// 範例 1-2：依序播放五種不同頻率，感受音調變化
// ============================================

int pinBuzzer = 8;

void setup() {
}

void loop() {
  tone(pinBuzzer, 262);  delay(400); noTone(pinBuzzer); delay(100);  // Do
  tone(pinBuzzer, 330);  delay(400); noTone(pinBuzzer); delay(100);  // Mi
  tone(pinBuzzer, 392);  delay(400); noTone(pinBuzzer); delay(100);  // Sol
  tone(pinBuzzer, 523);  delay(400); noTone(pinBuzzer); delay(100);  // 高音Do
  delay(1500);
}
```

#### 範例 1-3：tone() 的第三個參數 — 自動停止的持續時間
```cpp
// ============================================
// 範例 1-3：tone() 可以帶第三個參數指定持續時間，不需要手動 noTone()
// ============================================

int pinBuzzer = 8;

void setup() {
}

void loop() {
  tone(pinBuzzer, 1000, 200);   // 發出 1000Hz，持續 200 毫秒後自動停止
  delay(500);                    // 這裡的 delay 是讓兩次嗶聲之間有間隔
}
```
**教學重點**：`tone(pin, frequency, duration)` 這種寫法，會讓蜂鳴器發聲滿指定時間後「自動」停止，不需要另外呼叫 `noTone()`。但要注意，`delay()` 仍然是必要的，否則程式會立刻執行下一行，可能導致嗶聲被新的指令中斷。

### 關卡 2：音符與旋律 — 用陣列演奏簡單樂曲

**機關故事**：密室希望警報聲不只是單調的「嗶嗶嗶」，而要有一小段令人印象深刻的旋律，作為機關啟動的信號音。

#### 範例 2-1：用陣列儲存音符序列
```cpp
// ============================================
// 範例 2-1：用兩個陣列分別儲存「音符」與「拍長」，演奏簡單旋律
// ============================================

int pinBuzzer = 8;

// 音符頻率（Hz），數字越大音調越高
int melody[] = {523, 659, 784, 1047, 784, 659, 523};
// 每個音符對應的持續時間（毫秒）
int noteDurations[] = {300, 300, 300, 500, 300, 300, 500};
int numNotes = 7;

void setup() {
}

void loop() {
  for (int i = 0; i < numNotes; i++) {
    tone(pinBuzzer, melody[i], noteDurations[i]);
    delay(noteDurations[i] + 50);   // 每個音符之間留一點空隙，避免聲音黏在一起
  }
  noTone(pinBuzzer);
  delay(2000);   // 播放完畢後暫停久一點再重播
}
```
**教學重點**：這裡用了「兩個平行陣列」的技巧——`melody[]` 跟 `noteDurations[]` 的索引位置互相對應（`melody[0]` 配 `noteDurations[0]`，以此類推）。這是密室音效設計最實用的資料結構手法之一。

#### 範例 2-2：把旋律封裝成自訂函式
```cpp
// ============================================
// 範例 2-2：把播放旋律的邏輯封裝成函式，方便重複呼叫
// ============================================

int pinBuzzer = 8;

int melody[] = {523, 659, 784, 1047, 784, 659, 523};
int noteDurations[] = {300, 300, 300, 500, 300, 300, 500};
int numNotes = 7;

void playMelody() {
  for (int i = 0; i < numNotes; i++) {
    tone(pinBuzzer, melody[i], noteDurations[i]);
    delay(noteDurations[i] + 50);
  }
  noTone(pinBuzzer);
}

void setup() {
}

void loop() {
  playMelody();
  delay(2000);
}
```

### 關卡 3：光敏電阻 — 分壓電路與環境光偵測

**機關故事**：在做出警報邏輯前，你得先確認能穩定讀取環境光線的變化。

#### 範例 3-1：讀取光敏電阻類比值
```cpp
// ============================================
// 範例 3-1：讀取環境光線強度（0~1023）
// ============================================

int pinLdr = A1;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int lightLevel = analogRead(pinLdr);
  Serial.println(lightLevel);
  delay(200);
}
```
**操作提醒**：在 Tinkercad 中可以直接點擊光敏電阻元件，用滑桿調整「環境亮度」進行模擬測試，觀察數值即時變化。

#### 範例 3-2：正常光線 vs 遮蔽光線的門檻判斷
```cpp
// ============================================
// 範例 3-2：光線低於門檻時，RGB LED 切換為紅色警示
// ============================================

int pinLdr = A1;
int pinR = 9, pinG = 10, pinB = 11;
int threshold = 300;   // 光線門檻，低於此值視為「被遮蔽」

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
}

void loop() {
  int lightLevel = analogRead(pinLdr);

  if (lightLevel < threshold) {
    setColor(255, 0, 0);   // 遮蔽：紅色警示
  } else {
    setColor(0, 255, 0);   // 正常：綠色安全
  }
}
```

#### 範例 3-3：光線映射到聲音頻率（互動樂器效果）
```cpp
// ============================================
// 範例 3-3：光控特雷門琴 - 光線強弱即時轉換成音調高低
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;

void setup() {
}

void loop() {
  int lightLevel = analogRead(pinLdr);
  int frequency = map(lightLevel, 0, 1023, 100, 2000);   // 光線轉換為音頻
  tone(pinBuzzer, frequency);
}
```
**教學重點**：這裡直接把第 4 週學過的 `map()` 拿來用在完全不同的感測器上——這正說明了 `map()` 是一個「萬用轉換工具」，不管原始資料來自旋鈕還是光敏電阻，只要是連續數值，都能用同一套手法轉換成任何你需要的輸出範圍。

### 關卡 4：雷射防盜網 — 光線遮斷觸發警報

**機關故事**：密室的核心機關正式登場——玩家必須小心不要遮擋住模擬雷射的光線，一旦遮擋就會觸發警報。

#### 範例 4-1：基礎遮斷警報
```cpp
// ============================================
// 範例 4-1：光線被遮蔽時，蜂鳴器立刻響起警報
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int threshold = 300;

void setup() {
}

void loop() {
  int lightLevel = analogRead(pinLdr);

  if (lightLevel < threshold) {
    tone(pinBuzzer, 1500);
  } else {
    noTone(pinBuzzer);
  }
}
```

#### 範例 4-2：光遮斷計數器（模擬入侵次數統計）
```cpp
// ============================================
// 範例 4-2：計算「被遮蔽」的次數 - 只在「剛遮蔽的瞬間」計數一次
// 這是這週最重要的邏輯手法：偵測「狀態轉變」而非「持續狀態」
// ============================================

int pinLdr = A1;
int threshold = 300;
int breachCount = 0;
bool wasBlocked = false;   // 記錄「上一輪」是否處於被遮蔽狀態

void setup() {
  Serial.begin(9600);
}

void loop() {
  int lightLevel = analogRead(pinLdr);
  bool isBlocked = lightLevel < threshold;

  // 偵測「由未遮蔽變成遮蔽」的瞬間，才計數一次（避免物體停留時重複計數）
  if (isBlocked && !wasBlocked) {
    breachCount++;
    Serial.print("偵測到入侵！累計次數：");
    Serial.println(breachCount);
  }

  wasBlocked = isBlocked;
}
```
**教學重點**：這個「偵測狀態轉變」的手法，跟第 2 週學過的按鈕防彈跳邏輯（`currentState == HIGH && lastButtonState == LOW`）本質上是同一種思維——**只在「狀態剛剛改變」的那個瞬間做事，而不是狀態持續期間每一輪迴圈都重複觸發**。這是這學期會反覆用到的核心技巧，請務必熟悉。

#### 範例 4-3：警報鎖定機制（一旦觸發需要人工解除）
```cpp
// ============================================
// 範例 4-3：警報一旦觸發就持續響鈴，即使玩家離開光線也不會自動停止
// 情境：真實防盜系統通常需要人工輸入密碼或按鈕才能解除警報
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int threshold = 300;
bool alarmTriggered = false;

}

void loop() {

  }
}
```

### 關卡 5：聲光聯動 — 多重感應與音調映射

**機關故事**：單純的警報聲太單調，密室老闆希望警報的「急迫程度」能隨著玩家靠近雷射線的程度連續變化，越靠近警戒線、警報越急促。

#### 範例 5-1：依光線變化調整警報頻率
```cpp
// ============================================
// 範例 5-1：光線越暗（越接近完全遮蔽），警報音調越高越急促
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int threshold = 500;

void setup() {
}

void loop() {
  int lightLevel = analogRead(pinLdr);

  if (lightLevel < threshold) {
    // 在門檻以下的範圍內，光線越暗，頻率越高
    int frequency = map(lightLevel, threshold, 0, 500, 2500);
    tone(pinBuzzer, frequency);
  } else {
    noTone(pinBuzzer);
  }
}
```

#### 範例 5-2：三級警戒燈光（配合聲音急迫感）
```cpp
// ============================================
// 範例 5-2：光線分三個等級，分別對應不同的燈光與嗶聲節奏
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int pinR = 9, pinG = 10, pinB = 11;

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
}

void loop() {
  int lightLevel = analogRead(pinLdr);

  if (lightLevel > 600) {
    // 安全：光線充足
    setColor(0, 255, 0);
    noTone(pinBuzzer);
  } else if (lightLevel > 300) {
    // 警戒：光線稍微變暗，緩慢嗶聲
    setColor(255, 255, 0);
    tone(pinBuzzer, 800);
    delay(200);
    noTone(pinBuzzer);
    delay(400);
  } else {
    // 危險：光線幾乎被完全遮蔽，急促高頻警報
    setColor(255, 0, 0);
    tone(pinBuzzer, 2000);
    delay(80);
    noTone(pinBuzzer);
    delay(80);
  }
}
```

#### 範例 5-3：整合亮度與音調的雙重警示（進階練習範例）
```cpp
// ============================================
// 範例 5-3：同時用 RGB 亮度與蜂鳴器音調，雙重呈現危險程度
// 這是關卡 5 額外提供的第三個範例，示範如何把單一感測值同時餵給多種輸出
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int pinR = 9, pinG = 10, pinB = 11;

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
}

void loop() {
  int lightLevel = analogRead(pinLdr);

  if (lightLevel < 500) {
    // 光線越暗，紅色越強、音調越高，兩種輸出同步呈現危險程度
    int dangerLevel = map(lightLevel, 500, 0, 0, 255);
    int frequency = map(lightLevel, 500, 0, 400, 2000);

    setColor(dangerLevel, 0, 0);
    tone(pinBuzzer, frequency);
  } else {
    setColor(0, 255, 0);
    noTone(pinBuzzer);
  }
}
```
**教學重點**：這段程式碼再一次示範了第 4 週學過的「一個原始感測值，同時映射給多種不同輸出用途」的技巧——這裡 `lightLevel` 同時決定了顏色深淺與音調高低，讓玩家能同時透過「看」與「聽」感受到危險程度的連續變化，這正是優秀機關設計追求的「多重感官一致性」。

**機關故事**：整合本週所有技巧，打造完整的雷射防盜密室系統——分級聲光警示、入侵次數統計、警報鎖定機制，並加入一個「解除警報用的旋律」作為機關通過驗證的信號音（此處先簡化為固定播放，第 12 週學到鍵盤密碼後可以真正做出密碼解除）。

```cpp
// ============================================
// BOSS 關：終極雷射防盜密室 - 整合本週所有技巧
// 功能：三級聲光警示 + 入侵次數統計 + 警報鎖定 + 通關旋律
// ============================================

int pinLdr = A1;
int pinBuzzer = 8;
int pinR = 9, pinG = 10, pinB = 11;

int breachCount = 0;
bool wasBlocked = false;
bool alarmLocked = false;

int successMelody[] = {523, 659, 784, 1047};
int successDurations[] = {150, 150, 150, 400};
int numSuccessNotes = 4;

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void playSuccessMelody() {
  for (int i = 0; i < numSuccessNotes; i++) {
    tone(pinBuzzer, successMelody[i], successDurations[i]);
    delay(successDurations[i] + 30);
  }
  noTone(pinBuzzer);
}

void setup() {
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
  Serial.begin(9600);
  Serial.println("=== 雷射防盜網系統啟動 ===");
}

void loop() {
  int lightLevel = analogRead(pinLdr);
  bool isBlocked = lightLevel < 300;

  // --- 入侵偵測與計數 ---
  if (isBlocked && !wasBlocked) {
    breachCount++;
    alarmLocked = true;   // 一旦偵測到入侵，警報永久鎖定
    Serial.print("!!! 偵測到入侵，累計次數：");
    Serial.println(breachCount);
  }
  wasBlocked = isBlocked;

  // --- 聲光警示呈現 ---
  if (alarmLocked) {
    setColor(255, 0, 0);
    tone(pinBuzzer, 2000);
    delay(80);
    noTone(pinBuzzer);
    delay(80);
  } else if (lightLevel < 600) {
    setColor(255, 255, 0);   // 警戒中（尚未觸發鎖定）
  } else {
    setColor(0, 255, 0);     // 安全
  }

  // --- 模擬「通關驗證」：入侵次數達到特定值時（此處示範用 3 次代表玩家已放棄躲避、選擇正面通過並成功解除），播放通關旋律並重置系統 ---
  if (breachCount >= 3) {
    Serial.println(">>> 系統重新校準中 <<<");
    playSuccessMelody();
    breachCount = 0;
    alarmLocked = false;
    setColor(0, 0, 255);
    delay(1000);
  }
}
```
**教學重點**：這裡示範了「用某個累積條件（`breachCount >= 3`）觸發系統重置」的設計思路，這跟真實工業設備「累計異常次數達到門檻，觸發保養提醒或系統重啟」的邏輯是相通的。第 12 週學會鍵盤輸入後，我們會把這個「自動重置」機制改成「需要輸入正確密碼才能解除」，讓機關更接近真正的密室逃脫遊戲體驗。

## 常見錯誤除錯站

| 現象 | 可能原因 | 解決方式 |
|---|---|---|
| 蜂鳴器完全沒聲音 | 接線腳位錯誤，或忘記呼叫 `tone()` | 檢查 `pinBuzzer` 變數對應的實際接線腳位 |
| 蜂鳴器持續發出同一個聲音停不下來 | 忘記呼叫 `noTone()`，或迴圈邏輯讓 `tone()` 一直被重複呼叫 | 檢查是否所有該停止聲音的分支都正確呼叫 `noTone()` |
| 旋律播放聽起來黏在一起、分不清音符 | 音符之間沒有留間隔 | 在每個音符播放後加上一小段額外的 `delay()`（如範例 2-1 的 `+ 50`） |
| 光敏電阻數值完全不會變化 | 分壓電路接線錯誤，忘記接 10kΩ 電阻 | 對照分壓電路圖解，確認電阻與訊號線的位置正確 |
| 入侵計數器瘋狂累加（一瞬間跳好幾次） | 沒有使用「狀態轉變偵測」，而是持續判斷 | 檢查是否正確使用 `isBlocked && !wasBlocked` 的寫法 |
| 警報鎖定後永遠無法恢復正常 | 忘記設計解除機制 | 檢查是否有對應的重置邏輯（如 BOSS 關的 `breachCount >= 3` 判斷） |
| Serial Monitor 一直重複印出同一段文字洗版 | 印出的程式碼放在會持續成立的條件裡，沒有搭配狀態轉變偵測 | 檢查是否應該只在「事件發生的那一瞬間」印出訊息，而非每輪迴圈都印 |
| 旋律播放時，音符聽起來忽快忽慢不平均 | 每個音符的 `delay()` 時間沒有跟 `noteDurations[]` 對應好 | 確認 `delay(noteDurations[i] + 50)` 中的 `i` 索引與播放的音符一致 |

### 🔴 挑戰題
11. **音符資料庫重構**：把範例 2-1 的音符頻率（如 523, 659, 784...）改用有意義的名稱定義（例如 `#define NOTE_C5 523`），讓旋律陣列變成 `{NOTE_C5, NOTE_E5, NOTE_G5, ...}` 更容易閱讀（提示：`#define` 是這學期第一次接觸的巨集寫法，可以自行上網查詢語法用途）。
12. **雙感應器聯防系統**：想像密室加裝了第二顆光敏電阻（需自行擴充接線到 A2），設計一個「任一顆感應器偵測到遮蔽就觸發警報」的系統（提示：善用第 2 週學過的 `||` 邏輯）。
13. **警報升級機制**：修改 BOSS 關程式碼，讓入侵次數每累加一次，警報聲的基礎頻率就提高 200Hz（模擬系統越來越緊張的心理效果），直到達到重置門檻才恢復正常。
14. **旋律播放不中斷偵測（進階思考）**：範例 2-1 的旋律播放過程中大量使用 `delay()`，這段時間內光敏電阻的變化完全不會被偵測到。請討論這個問題可能造成什麼後果，並嘗試（進階選修）設計一個至少能在旋律播放間隙偵測一次感測器的克難解法。
15. **完全自訂聲光機關**：不參考任何範例，設計一個「你認為最有戲劇張力的聲光警報機關」，至少要用到：1 段旋律陣列、1 個狀態轉變偵測邏輯、1 個至少三段的分級警示系統。

## 反思與延伸討論

1. 這週我們用了「狀態轉變偵測」（`isBlocked && !wasBlocked`）這個手法來做入侵計數，這跟第 2 週按鈕防彈跳的邏輯本質上完全相同。請討論：為什麼這種「只在狀態改變瞬間觸發」的思維，會在這麼多不同的感測情境中反覆出現？你認為這是不是一種值得牢記的「通用設計模式」？
2. 光敏電阻與可變電阻都是透過「分壓電路」讓 Arduino 讀取類比數值，但一個是「使用者主動旋轉」控制，一個是「環境被動影響」控制。請討論：這種「輸入來源不同、但電路原理相同」的現象，在工業感測器設計中還能找到哪些例子？
3. BOSS 關程式碼中，`playSuccessMelody()` 函式播放旋律時會用掉將近 1 秒鐘的時間，這段期間內程式完全無法偵測光敏電阻的變化。你認為這是否會造成安全隱憂？如果這是一套真實的防盜系統，你會如何改善這個設計缺陷？
4. 想像你是密室的營運者，需要向玩家解釋這套雷射防盜網系統「為什麼有時候感覺反應特別靈敏，有時候又感覺遲鈍」。結合本週學到的分壓電路特性與模擬環境的光線設定，你會怎麼向不懂程式的玩家解釋這個現象？
