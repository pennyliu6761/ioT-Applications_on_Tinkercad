# 第 5 週：會發聲、會看光的智慧場域

## 主題專案：聽得到的警示，看得見的光線

> 🎯 **本週定位**：到目前為止，系統只會用「燈」跟人溝通，輸入也都要靠人動手（按、轉）。這一週加入兩個新元件：
>
> - **蜂鳴器**：讓系統「發出聲音」提醒人
> - **光敏電阻**：讓系統「自己感覺」環境變亮或變暗，不需要人操作
>
> 和第 4 週一樣，本週**重點在配線**。每一個關卡都照「五個固定環節」進行：抽**客戶限制卡** → 回答**接線前決策題** → 照**接線任務**一步步接 → 套用**程式模板**（只改腳位區、參數區） → 完成**配線變化挑戰**（程式一個字都不改，只改線）。
>
> 🏁 **本週成果**：完成 **4 個關卡**（各存一個 Tinkercad 檔案）＋ **練習題 Lv.1～Lv.6**（套用本週的程式模板 T5～T8，配出不同的電路）。

## 認識新元件：蜂鳴器與光敏電阻

### 🔊 蜂鳴器（Piezo）

蜂鳴器有 **2 隻腳**，接法和單色 LED 很像，但**不需要電阻**：

| 蜂鳴器的腳 | 接到哪裡 |
| --- | --- |
| 正極（+，紅線） | 任何一隻數位腳位（也可以借 A 腳） |
| 負極（−，黑線） | GND |

- 蜂鳴器接在一般腳位就可以發聲，**不需要佔用 `~` 腳**。
- 音高數字越大，聲音越尖（例如 262 是 Do、523 是高八度的 Do）。本週模板的參數區可以直接改音高。

> ⚠️ **重要規則**：蜂鳴器發聲時，Arduino 內部會「借走」一部分計時資源，導致 **`~3` 和 `~11` 這兩隻腳的調光、混色失效**。所以只要同時用到蜂鳴器與需要調光的燈，**那些燈請避開 3 和 11，從 5、6、9、10 裡面挑**。

### 🌗 光敏電阻（Photoresistor）

光敏電阻有 **2 隻腳**，要搭配一顆 **10kΩ 電阻**，接法和第 2 週的按鈕幾乎一樣：

> **一腳接 5V，另一腳同時接「A 腳」和「10kΩ 到 GND」。**

```
  5V
   │
光敏電阻
   │
   ├──────── 接到 A0～A5
   │
10kΩ 電阻
   │
  GND
```

| 光線狀況 | 讀到的數字 |
| --- | --- |
| 很亮 | 數字大（接近 1023） |
| 很暗、被遮住 | 數字小（接近 0） |

- 在 Tinkercad 開始模擬後，**點一下光敏電阻**，會出現一條亮度滑桿，拖曳它就能模擬變亮或變暗。
- 每一顆光敏電阻都需要**自己的** 10kΩ 電阻和**自己的** A 腳。

### 🧭 三種「A 腳輸入元件」比一比

| 元件 | 誰來改變數值？ | 需要 10kΩ 嗎？ |
| --- | --- | --- |
| 按鈕（第 2 週） | 人按下 | 要 |
| 旋鈕（第 4 週） | 人轉動 | 不用 |
| 光敏電阻（本週） | **環境光線自己變** | 要 |

## 本週三個配線新技巧

這三招會在「配線變化挑戰」中反覆用到，**全部都不用改程式**。

### 🔧 技巧 1：兩顆燈共用一隻腳

客戶要「兩個地方同時亮」（例如櫃台和診間門口），但腳位不夠時：

```
Arduino 腳位 ──┬── 220Ω ── LED① ── GND
               └── 220Ω ── LED② ── GND
```

- 從同一隻腳拉出**兩條線**，**每顆燈各自串一顆 220Ω**，不能兩顆共用一顆電阻。
- 兩顆燈會**完全同步**：一起亮、一起滅、一起變亮變暗。
- 一隻腳最多這樣接 **2 顆**，再多 Arduino 會吃不消。

### 🔧 技巧 2：光敏電阻和 10kΩ 對調，讀值就反過來

```
原本：5V ── 光敏電阻 ──┬── 10kΩ ── GND    → 亮時數字大
                        └── A 腳

對調：5V ── 10kΩ ──┬── 光敏電阻 ── GND    → 亮時數字小
                    └── A 腳
```

- 客戶要「變亮才觸發」，而程式寫的是「變暗才觸發」？**把兩顆零件的位置對調就好**。
- 這是工程師常用的「硬體反相」技巧。

### 🔧 技巧 3：只用全亮全滅的顏色，RGB 就不必接 `~` 腳

- 紅、綠、藍、黃（紅＋綠）、青（綠＋藍）、紫（紅＋藍）、白，這 7 種顏色每個顏色腳**不是 0 就是 255**。
- 這種顏色接在**一般腳位**也能正確顯示（Arduino 會把 255 當成全亮、0 當成全滅）。
- 只有**混出中間色**（例如橘色 255,140,0、淡藍 0,0,60）時，才一定要 `~` 腳。
- 當 `~` 腳不夠分（尤其有蜂鳴器時），這招很好用。

## 配線口訣卡

| 口訣 | 說明 |
| --- | --- |
| ① 要調亮度、混中間色 → 接 `~` 腳 | 只有 3、5、6、9、10、11 |
| ② **有蜂鳴器時，需要調光的燈避開 3、11** | 從 5、6、9、10 裡挑 |
| ③ 只要亮或滅、蜂鳴器、按鈕 → 一般腳位就好 | 把 `~` 腳留給需要調光的燈 |
| ④ 每條燈線一顆 220Ω；蜂鳴器、旋鈕不用 | 兩顆燈共用一隻腳時，**每顆各自一顆** 220Ω |
| ⑤ 光敏電阻：一腳 5V，一腳接 A 腳＋10kΩ 到 GND | 對調兩顆零件，讀值反過來 |
| ⑥ 旋鈕：兩邊接電源，中間接 A 腳 | 不用電阻 |
| ⑦ Pin 0、1 先不要用；腳位不夠時借 A 腳 | A 腳也能接燈、按鈕、蜂鳴器 |
| ⑧ 方向反了 → 先改線，不改程式 | 旋鈕兩腳對調、光敏電阻與 10kΩ 對調、燈換位置 |

## 共用工具

### 🔧 工具 1：類比讀值檢查器（旋鈕、光敏電阻都適用）

接好光敏電阻後，先用這支程式確認它有反應，並**記下「最亮」和「最暗」各讀到多少**——參數區的門檻要依這兩個數字決定。

```cpp
int pinSensor = A0;   // ← 改成你接的 A 腳

void setup() {
  Serial.begin(9600);
}

void loop() {
  Serial.println(analogRead(pinSensor));
  delay(100);
}
```

**記錄表**（每次接光敏電阻都要填）：

| 光敏電阻 | 接在 | 滑桿最亮 | 滑桿最暗 | 我設定的門檻 |
| --- | --- | --- | --- | --- |
| 第 1 顆 | A? | | | |
| 第 2 顆 | A? | | | |

> 💡 門檻要設在「最亮」和「最暗」的中間附近，離兩端都留一段距離，才不會誤判。

### 🔧 工具 2：接線驗證器（沿用第 3、4 週）

```cpp
int pins[] = { 9, 10, 11 };   // ← 填入所有「燈」的腳位（不含蜂鳴器）
int numPins = 3;

void setup() {
  Serial.begin(9600);
  for (int i = 0; i < numPins; i++) pinMode(pins[i], OUTPUT);
}

void loop() {
  for (int i = 0; i < numPins; i++) {
    Serial.print("Testing Pin ");
    Serial.println(pins[i]);
    digitalWrite(pins[i], HIGH);
    delay(500);
    digitalWrite(pins[i], LOW);
  }
  Serial.println("---");
  delay(1000);
}
```

### 🔧 工具 3：蜂鳴器測試器

接好蜂鳴器後，跑一次「Do Re Mi Fa Sol」，確認有聲音。（記得打開電腦喇叭）

```cpp
int pinBuzzer = 8;   // ← 改成你蜂鳴器接的腳位
int notes[] = { 262, 294, 330, 349, 392 };

void setup() {
  for (int i = 0; i < 5; i++) {
    tone(pinBuzzer, notes[i], 300);
    delay(400);
  }
}

void loop() {
}
```

## 關卡 1：診所叫號服務鈴（模板 T5）

⭐ **難度**：按鈕 ＋ 蜂鳴器，再逐步加燈和旋鈕

### 📖 情境

社區診所的櫃台要一顆叫號鈴。護理師按一下按鈕，就發出「叮咚」聲，叫號燈閃爍，同時在螢幕（Serial Monitor）顯示目前號碼。診所有好幾個診間，希望各診間的叮咚聲**音高不同**，病人一聽就知道是哪一間在叫號。

### 🎯 本關配線學習目標

- 第一次接蜂鳴器：分辨正負極、判斷要不要 `~` 腳
- 用「技巧 1」讓兩顆燈共用一隻腳

### 🃏 ① 客戶限制卡

| 限制卡 | 現場條件 |
| --- | --- |
| **A** | 診間 **3** 間；蜂鳴器必須接 **Pin 8**；叫號燈 1 顆 |
| **B** | 診間 **4** 間；Pin 2～6 已被掛號系統佔用；叫號燈 1 顆 |
| **C** | 診間 **2** 間；叫號鈕必須接 **A3**；叫號燈要 **2 顆同時亮**（櫃台一顆、候診區一顆），但**只能用 1 隻腳** |

### ✏️ ② 接線前決策題

1. 蜂鳴器需要電阻嗎？叫號燈需要嗎？本關一共需要幾顆 220Ω、幾顆 10kΩ？（限制卡 C 要特別算）
2. 蜂鳴器和叫號燈都只需要「開／關」，需要 `~` 腳嗎？
3. 診間選擇旋鈕要接哪裡？
4. 你的限制卡有幾間診間？參數區的 `numRooms` 和 `roomTone[]` 要怎麼改？請先寫下每間診間要用的音高（音高要明顯不同，建議相差 150 以上）。

**腳位規劃表**：

| 元件 | 腳位 | 為什麼這樣選？ |
| --- | --- | --- |
| 叫號按鈕 | | |
| 蜂鳴器（+） | | |
| 叫號燈（限制卡 C：兩顆共用） | | |
| 診間選擇旋鈕（中間腳） | | |

**音高規劃表**：

| 診間 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| 音高 | | | | |

### 🔌 ③ 接線任務

**Step 1：按鈕＋蜂鳴器**

1. 按鈕跨在麵包板中間凹槽，一側接 5V，另一側接訊號線到你規劃的腳位，同側再接 10kΩ 到 GND。
2. 蜂鳴器正極（紅線、+）接你規劃的腳位，負極接 GND。**不用電阻。**
3. ✅ 檢查：用**工具 3** 確認蜂鳴器有聲音。

**Step 2：加上叫號燈**

1. 叫號燈長腳串 220Ω 接你規劃的腳位，短腳接 GND。
2. 限制卡 C：從同一隻腳拉**兩條線**，各自串一顆 220Ω 到兩顆燈，兩顆燈分別放在麵包板兩端（模擬櫃台和候診區）。
3. ✅ 檢查：用**工具 2** 確認燈會亮（限制卡 C：兩顆要同時亮）。

**Step 3：加上診間選擇旋鈕**

1. 旋鈕兩邊接 5V、GND，中間腳接你規劃的 A 腳。
2. ✅ 檢查：用**工具 1** 確認 0～1023。

### 💻 ④ 套用程式模板 T5

```cpp
// ===== 程式模板 T5：叫號鈴 =====

// ----- 腳位區（沒接的元件填 -1）-----
int pinCall   = ?;                  // 叫號按鈕
int pinBuzzer = ?;                  // 蜂鳴器
int pinLight  = ?;                  // 叫號燈
int pinKnob   = A0;                 // 診間選擇旋鈕

// ----- 參數區 -----
int numRooms = 3;                   // 診間數量（1~6）
int roomTone[6] = { 660, 880, 1047, 0, 0, 0 };   // 各診間「叮」的音高
```

```cpp
  Serial.print(low);
```

```cpp
// ===== 程式模板 T8：光柵計數＋第二感測器警報 =====

// ----- 腳位區（沒接的元件填 -1）-----
int ldrLine = A0;                              // 計數用光敏電阻
int ldrBin  = A1;                              // 第二個光敏電阻（例如原料箱）
int bar[8] = { ?, ?, ?, ?, ?, -1, -1, -1 };    // 批次燈，依「第一個就亮」順序填
int numBars = 5;                               // 批次燈數量＝每批幾個（2~8）
int pinR = ?, pinG = ?, pinB = ?;              // 狀態 RGB
int pinBuzzer = ?;                             // 蜂鳴器
int pinReset  = ?;                             // 歸零鈕

// ----- 參數區 -----
int lineThreshold = 300;                       // 計數感測器門檻
bool lineTriggerDark = true;                   // true：變暗算經過一個；false：變亮算
int binThreshold = 300;                        // 第二感測器門檻
bool binAlarmWhenBright = true;                // true：變亮時警報；false：變暗時警報
String itemName = "Box";                       // 計數物品名稱（英文）
String binMsg   = "Material bin EMPTY";        // 第二感測器警報訊息（英文）
int countTone = 2000;                          // 每計一個的嗶聲音高
int melody[3] = { 523, 659, 784 };             // 滿一批的提示旋律
int binTone = 300;                             // 第二感測器警報音高

// ----- 功能開關 -----
bool useBin   = false;                         // Step 2：第二感測器＋RGB
bool useReset = false;                         // Step 3：歸零鈕

// ===== 以下不用改 =====
bool wasPass = false, wasAlarm = false;
int count = 0, lastButton = LOW;

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  for (int i = 0; i < numBars; i++) pinMode(bar[i], OUTPUT);
  if (useBin) { pinMode(pinR, OUTPUT); pinMode(pinG, OUTPUT); pinMode(pinB, OUTPUT); }
  if (useReset) pinMode(pinReset, INPUT);
  Serial.begin(9600);
}

void loop() {
  int l = analogRead(ldrLine);
  bool pass = lineTriggerDark ? (l < lineThreshold) : (l > lineThreshold);
  if (pass && !wasPass) {
    count++;
    Serial.print(itemName + " #");
    Serial.println(count);
    if (count % numBars == 0) {
      Serial.println("=== Batch complete ===");
      for (int i = 0; i < 3; i++) { tone(pinBuzzer, melody[i], 150); delay(200); }
    } else {
      tone(pinBuzzer, countTone, 80);
    }
  }
  wasPass = pass;

  int inBatch = count % numBars;
  if (count > 0 && inBatch == 0) inBatch = numBars;
  for (int i = 0; i < numBars; i++) digitalWrite(bar[i], (i < inBatch) ? HIGH : LOW);

  if (useBin) {
    int b = analogRead(ldrBin);
    bool alarm = binAlarmWhenBright ? (b > binThreshold) : (b < binThreshold);
    if (alarm && !wasAlarm) {
      Serial.println("WARNING: " + binMsg);
      tone(pinBuzzer, binTone, 600);
    }
    wasAlarm = alarm;
    if (alarm) setColor(255, 0, 0);
    else       setColor(0, 255, 0);
  }

  if (useReset) {
    int now = digitalRead(pinReset);
    if (now == HIGH && lastButton == LOW) {
      delay(50);
      Serial.print("Shift total: ");
      Serial.println(count);
      count = 0;
    }
    lastButton = now;
  }
  delay(30);
}
```

## 配線除錯站

| 現象 | 先檢查這裡 | 修正方式 |
| --- | --- | --- |
| 蜂鳴器完全沒聲音 | 正極是否接到程式裡的腳位、負極是否接 GND；電腦喇叭是否打開 | 用工具 3 測試 |
| 蜂鳴器一直響停不下來 | 門檻設定、觸發方向參數 | 用工具 1 看讀值，重新設門檻 |
| 光敏電阻讀值一直是 0 或 1023 | 10kΩ 是否接到 GND、A 腳是否接在兩顆零件的交界處 | 照接法重接 |
| 觸發方向和預期相反 | 光敏電阻與 10kΩ 的位置；`triggerWhenDark` 參數 | 技巧 2，或改參數 |
| 警報響時 RGB 顏色怪怪的 | 需要調光的顏色是否接在 3 或 11 | 改接 5、6、9、10，或改用全亮全滅顏色 |
| 兩顆燈共用一隻腳，一顆很暗 | 兩顆是否共用一顆電阻 | 每顆各自一顆 220Ω |
| 擋一次光，計數卻一直跳 | 門檻是否剛好卡在讀值附近 | 依記錄表重新設定門檻 |
| 程式無法上傳 | 腳位區是否還有 `?` 沒填 | 用到的填腳位，沒接的填 `-1` |

## 📖 本週詞彙表

| 名稱 | 白話解釋 |
| --- | --- |
| 蜂鳴器（Piezo Buzzer） | 能發出嗶聲或簡單旋律的輸出元件，接一般腳位、不用電阻 |
| 音高（頻率，Hz） | 數字越大聲音越尖，例如 262 是 Do、523 是高音 Do |
| 光敏電阻（Photoresistor） | 依環境亮暗給出 0～1023 數值的感測器，要搭配 10kΩ |
| 光柵 | 一道光照在感測器上，被擋住就代表有人或物體經過 |
| 門檻（Threshold） | 判斷「亮／暗」或「有／沒有」的分界數字 |
| 狀態改變偵測 | 只在「剛被擋住」那一瞬間做一次動作，避免重複計數 |
| 警報鎖定（Latch） | 警報觸發後不會自己停，必須有人確認解除 |
| 硬體反相 | 把光敏電阻和 10kΩ 對調，讓讀值方向相反 |
| 共用腳位並聯 | 兩顆燈各串電阻、接同一隻腳，同步亮滅 |

## 反思與延伸討論

1. 本週同一種光敏電阻，有時「變暗＝有事」（光柵、還書口），有時「變亮＝有事」（冰箱門、原料箱、展示櫃）。決定方向的關鍵是什麼？以後遇到新感測器時，你會先問自己哪些問題？
2. 「技巧 2」讓你不改程式就能反轉感測器方向。在真實的產品開發中，「改硬體」和「改軟體」各有什麼成本？
3. 本週好幾題都遇到「誤觸發」：貓經過光柵、烏雲讓路燈亮、兩本書一起投入。誤觸發太多，使用者會開始「忽略警報」。從管理的角度，這會帶來什麼風險？
