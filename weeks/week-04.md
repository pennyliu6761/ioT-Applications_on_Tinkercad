# 第 4 週：旋鈕控制的智慧場域

## 主題專案：一顆旋鈕，四種現場

> 🎯 **本週定位**：前三週的輸入只有「按下／放開」兩種狀態。這一週加入新元件 **旋鈕（可變電阻）**，它可以「轉多少、就給多少」，讓使用者用連續的方式調整數值。

## 認識新元件：旋鈕

### 外觀與接法

旋鈕有 **3 隻腳**，接法固定，只要記住一句話：

> **兩邊接電源，中間接 A 腳。**

| 旋鈕的腳 | 接到哪裡 |
| --- | --- |
| 左腳 | 5V（或 GND） |
| **中間腳** | **A0～A5 其中一隻** |
| 右腳 | GND（或 5V） |

- 左右兩腳接反沒關係，只是旋轉方向會相反（轉左變大、轉右變小）。**這是本週「配線變化挑戰」常用的技巧。**
- 旋鈕**不需要**另外接電阻。
- 在 Tinkercad 開始模擬後，用滑鼠按住旋鈕拖曳就能轉動。

### 旋鈕讀到的數字

- 轉到一端讀到 **0**，轉到另一端讀到 **1023**，中間是連續變化的數字。
- 現場人員不會想看「735」這種數字，他們要看「72%」、「第 3 段」、「中速」——這就是換算機要做的事。

### 換算機 `map()`：只需要會「填空」

```cpp
map(讀到的數字, 0, 1023, 你要的最小值, 你要的最大值)
```

| 你想要的結果 | 這樣寫 |
| --- | --- |
| 換算成 0～100% | `map(讀值, 0, 1023, 0, 100)` |
| 換算成 LED 亮度 0～255 | `map(讀值, 0, 1023, 0, 255)` |
| 轉越多、數字越小（反向） | `map(讀值, 0, 1023, 400, 50)` |

> 💡 本週的程式模板都已經寫好換算。你只要在「參數區」填入「最小值」「最大值」就好。

## 配線口訣卡

| 口訣 | 說明 |
| --- | --- |
| ① 旋鈕：兩邊接電源，中間接 A 腳 | 中間腳接 A0～A5 |
| ② 要調亮度、要混色 → 接 `~` 腳 | 只有 3、5、6、9、10、11 |
| ③ 只要亮或滅 → 一般腳位就好 | 把 `~` 腳留給需要的燈 |
| ④ 按鈕不要佔 `~` 腳 | 按鈕只需要讀「有沒有按」 |
| ⑤ 每條燈線一顆 220Ω | RGB LED 三個顏色腳各一顆；旋鈕不用電阻 |
| ⑥ Pin 0、1 先不要用 | 它們負責和 Serial Monitor 通訊 |
| ⑦ 腳位不夠時，A 腳也能借用 | 沒接旋鈕的 A 腳，可以當一般腳位接燈或按鈕（但不能調光） |
| ⑧ 方向反了 → 先改線，不改程式 | 旋鈕左右兩腳對調；燈的順序就把線換位置 |

## 共用工具

### 🔧 工具 1：旋鈕讀值檢查器

接好旋鈕後先跑這支，確認旋鈕真的有反應。開啟 Serial Monitor 看數字，或切換到 **Serial Plotter** 看折線圖。

```cpp
int pinKnob = A0;   // ← 改成你旋鈕接的 A 腳

void setup() {
  Serial.begin(9600);
}

void loop() {
  Serial.println(analogRead(pinKnob));
  delay(50);
}
```

**檢查標準**：轉到底是 0，轉到另一端是 1023，中間平順變化。

### 🔧 工具 2：接線驗證器（沿用第 3 週）

```cpp
int pins[] = { 9, 10, 11 };   // ← 填入所有「燈」的腳位，依你希望的順序
int numPins = 3;              // ← 腳位數量

void setup() {
  Serial.begin(9600);
  for (int i = 0; i < numPins; i++) pinMode(pins[i], OUTPUT);
}

void loop() {
  for (int i = 0; i < numPins; i++) {
    Serial.print("Testing Pin ");
    Serial.println(pins[i]);
    digitalWrite(pins[i], HIGH);
    delay(500);
    digitalWrite(pins[i], LOW);
  }
  Serial.println("---");
  delay(1000);
}
```

**檢查標準**：燈依照你在陣列裡填的順序亮起，而且順序和麵包板上的擺放位置一致。

## 關卡 1：會議室智慧照明（模板 T1）

⭐ **難度**：1 顆旋鈕 ＋ 輸出由少變多

### 📖 情境

共享辦公室的會議室想要一套照明系統。用一顆旋鈕調整燈光：調暗時是溫暖的黃光（適合討論），調亮時是明亮的冷白光（適合簡報）。會議結束時，按一下按鈕就能全部關燈。

### 🎯 本關配線學習目標

- 第一次接旋鈕：分辨三隻腳、選一隻 A 腳
- 判斷哪些燈需要 `~` 腳，並在限制條件下重新分配

### 🃏 ① 客戶限制卡

| 限制卡 | 現場條件 |
| --- | --- |
| **A** | 舊設備已經佔用了 **~9、~10**，不能使用 |
| **B** | 客戶指定照明燈必須接在 **~3**；旋鈕必須接 **A2** |
| **C** | 舊設備已經佔用了 **~5、~6**；按鈕必須接在 **A 腳**（借用） |

### ✏️ ② 接線前決策題（先寫答案再接線）

1. 本關需要：照明燈 1 顆、RGB LED 1 顆、按鈕 1 顆、旋鈕 1 顆。請算出一共需要幾顆 **220Ω**？幾顆 **10kΩ**？
2. 照明燈要「無段調光」，RGB 要「平滑漸變顏色」。這兩個元件共需要幾隻 `~` 腳？
3. 依你的限制卡，扣掉不能用的腳後，還剩哪幾隻 `~` 腳？夠不夠分？
4. 按鈕可以接 `~` 腳嗎？依口訣④，你會怎麼選？

**腳位規劃表**：

| 元件 | 腳位 | 是 `~` 腳嗎？ | 為什麼這樣選？（限制卡怎麼影響你） |
| --- | --- | --- | --- |
| 調光旋鈕（中間腳） | | — | |
| 照明燈（白色 LED） | | | |
| RGB 紅 R | | | |
| RGB 綠 G | | | |
| RGB 藍 B | | | |
| 總開關按鈕 | | | |

### 🔌 ③ 接線任務

**Step 1：旋鈕＋照明燈**

1. 把旋鈕放在麵包板**左側**，左腳接 5V 電源軌、右腳接 GND 電源軌。
2. 中間腳拉一條線到你規劃的 A 腳。
3. 照明燈放在麵包板**右側**：長腳（正極）串一顆 220Ω 後接到你規劃的 `~` 腳；短腳接 GND。
4. ✅ 檢查：用**工具 1** 確認旋鈕 0～1023；用**工具 2** 確認照明燈會亮。

**Step 2：加上 RGB LED**

1. RGB LED 放在照明燈旁邊。最長的腳（共陰極）接 GND。
2. R、G、B 三隻腳**各串一顆 220Ω**，再接到你規劃的三隻 `~` 腳。
3. ✅ 檢查：用**工具 2**（填入 R、G、B 三個腳位），確認紅、綠、藍依序亮起。

**Step 3：加上總開關按鈕**

1. 按鈕跨在麵包板中間的凹槽上。
2. 一側接 5V；另一側接一條訊號線到你規劃的腳位，同一側再接一顆 10kΩ 到 GND。
3. ✅ 檢查：麵包板上的元件分成「輸入區（旋鈕、按鈕）」和「輸出區（燈）」兩區。

### 💻 ④ 套用程式模板 T1

```cpp
// ===== 程式模板 T1：旋鈕調光 =====

// ----- 腳位區：填你的腳位規劃表（沒接的元件填 -1）-----
int pinKnob  = A0;                  // 調光旋鈕
int pinLamp  = ?;                   // 單色照明燈（~ 腳）
int pinR = ?, pinG = ?, pinB = ?;   // RGB（~ 腳）
int pinPower = ?;                   // 總開關按鈕

// ----- 參數區：依情境調整 -----
int minBright = 0;                  // 旋鈕轉到最小時的照明亮度（0~255）
int maxBright = 255;                // 旋鈕轉到最大時的照明亮度（0~255）
int lowR = 255, lowG = 100, lowB = 0;      // 旋鈕在最小時的 RGB 顏色（暖黃）
int highR = 150, highG = 200, highB = 255; // 旋鈕在最大時的 RGB 顏色（冷白）

// ----- 功能開關：接好對應元件後改成 true -----
bool useLamp   = false;             // Step 1：照明燈
bool useRGB    = false;             // Step 2：RGB
bool useButton = false;             // Step 3：總開關按鈕

// ===== 以下不用改 =====
bool systemOn = true;
int lastButton = LOW;

void setup() {
  if (useLamp) pinMode(pinLamp, OUTPUT);
  if (useRGB) { pinMode(pinR, OUTPUT); pinMode(pinG, OUTPUT); pinMode(pinB, OUTPUT); }
  if (useButton) pinMode(pinPower, INPUT);
  Serial.begin(9600);
}

void loop() {
  if (useButton) {
    int now = digitalRead(pinPower);
    if (now == HIGH && lastButton == LOW) {
      delay(50);
      systemOn = !systemOn;
      Serial.println(systemOn ? "Lights ON" : "Lights OFF");
    }
    lastButton = now;
  }

  int knob = analogRead(pinKnob);
  int bright = systemOn ? map(knob, 0, 1023, minBright, maxBright) : 0;

  if (useLamp) analogWrite(pinLamp, bright);
  if (useRGB) {
    analogWrite(pinR, systemOn ? map(knob, 0, 1023, lowR, highR) : 0);
    analogWrite(pinG, systemOn ? map(knob, 0, 1023, lowG, highG) : 0);
    analogWrite(pinB, systemOn ? map(knob, 0, 1023, lowB, highB) : 0);
  }
  delay(20);
}
```

**本關要改的地方**：

| 區塊 | 要做什麼 |
| --- | --- |
| 腳位區 | 依你的腳位規劃表填入（限制卡 B 的旋鈕記得改成 `A2`） |
| 參數區 | 本關不用改 |
| 功能開關 | Step 1 接好 → `useLamp = true`；Step 2 → `useRGB = true`；Step 3 → `useButton = true` |

### 🔄 ⑤ 配線變化挑戰（程式一個字都不能改）

| 客戶臨時要求 | 你要改哪幾條線？ |
| --- | --- |
| 「旋鈕往**右**轉應該是**變亮**」，但你接好後剛好相反 | |
| 「藍色太刺眼，冷白光時不要有藍色」 | |
| 「照明燈要放在 RGB 的左邊，而且要換一隻 `~` 腳」（換到哪一隻？程式會怎樣？） | |

> 💡 第 3 題是陷阱題：換了腳位，程式的腳位區就**必須**跟著改。請說明為什麼「改線」和「改腳位區」要一起做。

### 💼 情境思考

1. 為什麼會議室要讓使用者自己調光，而不是固定亮度？從節能、使用者滿意度兩個面向討論。

// ----- 腳位區（沒接的填 -1）-----
int pinKnob = A0;                          // 速度旋鈕
int lane[8] = { ?, ?, ?, ?, ?, -1, -1, -1 };  // 指示燈，依「跑動順序」填
int numLanes = 5;                          // 實際接了幾顆指示燈（2~8）
int pinR = ?, pinG = ?, pinB = ?;          // 狀態 RGB
int pinStop = ?;                           // 停機鈕

// ----- 參數區 -----
int slowDelay = 400;                       // 最慢時每一步間隔（毫秒）
int fastDelay = 50;                        // 最快時每一步間隔（毫秒）
int lowLine  = 30;                         // 旋鈕低於這個 % 算「低速區」
int highLine = 80;                         // 旋鈕高於這個 % 算「高速區」
int colorLow[3]  = { 0, 0, 255 };          // 低速區顏色（藍）
int colorMid[3]  = { 0, 255, 0 };          // 中速區顏色（綠）
int colorHigh[3] = { 255, 180, 0 };        // 高速區顏色（黃）
int colorStop[3] = { 255, 0, 0 };          // 停機顏色（紅）

// ----- 功能開關 -----
bool useRGB    = false;                    // Step 2
bool useButton = false;                    // Step 3

// ===== 以下不用改 =====
bool stopped = false;
int lastButton = LOW;
int pos = 0;

void setColor(int c[]) {
  analogWrite(pinR, c[0]);
  analogWrite(pinG, c[1]);
  analogWrite(pinB, c[2]);
}

void setup() {
  for (int i = 0; i < numLanes; i++) pinMode(lane[i], OUTPUT);
  if (useRGB) { pinMode(pinR, OUTPUT); pinMode(pinG, OUTPUT); pinMode(pinB, OUTPUT); }
  if (useButton) pinMode(pinStop, INPUT);
  Serial.begin(9600);
}

void loop() {
  if (useButton) {
    int now = digitalRead(pinStop);
    if (now == HIGH && lastButton == LOW) {
      delay(50);
      stopped = !stopped;
      Serial.println(stopped ? "STOPPED" : "RUNNING");
    }
    lastButton = now;
  }

  if (stopped) {
    for (int i = 0; i < numLanes; i++) digitalWrite(lane[i], LOW);
    if (useRGB) setColor(colorStop);
    delay(20);
    return;
  }

  int percent = map(analogRead(pinKnob), 0, 1023, 0, 100);
  int stepDelay = map(percent, 0, 100, slowDelay, fastDelay);

  if (useRGB) {
    if (percent < lowLine)       setColor(colorLow);
    else if (percent <= highLine) setColor(colorMid);
    else                          setColor(colorHigh);
  }

  for (int i = 0; i < numLanes; i++) {
    digitalWrite(lane[i], (i == pos) ? HIGH : LOW);
  }
  pos = (pos + 1) % numLanes;
  delay(stepDelay);
}
```

| 區塊 | 要做什麼 |
| --- | --- |
| 腳位區 | `lane[]` 依**跑動順序**填腳位；`numLanes` 改成你的燈數；不用的位置保持 `-1` |
| 參數區 | 本關不用改 |
| 功能開關 | Step 2 → `useRGB = true`；Step 3 → `useButton = true` |

> ⏱️ **操作提示**：輸送帶慢速時，停機鈕請按住約半秒再放開（程式在等待下一步時不會讀按鈕）。

### 🔌 ③ 接線任務

**Step 1：選項 A 旋鈕＋選項 A 燈**

1. 選項 A 的燈排成一排，放在麵包板**上半部**，旋鈕放在這排燈的左邊。

3. ✅ 檢查：用**工具 2** 確認順序。

**Step 2：選項 B 旋鈕＋選項 B 燈**

1. 選項 B 的燈放在麵包板**下半部**，和選項 A 隔開至少 3 列。旋鈕放在這排燈的左邊。

3. 依你的腳位規劃表，借用的 A 腳在這一步接上。
4. ✅ 檢查：用**工具 2** 確認選項 B 燈的順序（A 腳可以直接填 `A2`、`A3` 等）。

**Step 3：確認燈 RGB＋下單鈕**

// ----- 腳位區（沒接的填 -1）-----
int knobA = A0, knobB = A1;                    // 選項 A、B 旋鈕
int ledA[8] = { ?, ?, ?, ?, ?, -1, -1, -1 };   // 選項 A 的燈，依段數順序填
int countA  = 5;                               // 選項 A 有幾段（2~8）
int ledB[8] = { ?, ?, ?, ?, -1, -1, -1, -1 };  // 選項 B 的燈，依段數順序填
int countB  = 4;                               // 選項 B 有幾段（2~8）
int pinR = ?, pinG = ?, pinB = ?;              // 確認燈 RGB
int pinOrder = ?;                              // 下單鈕

// ----- 參數區 -----
String nameA = "Sugar";                        // 選項 A 名稱（英文）
String nameB = "Ice";                          // 選項 B 名稱（英文）
String labelA[8] = { "0%", "30%", "50%", "70%", "100%", "", "", "" };
String labelB[8] = { "No ice", "Light", "Less", "Normal", "", "", "", "" };
bool fillMode = true;                          // true：亮到第幾段（長條）；false：只亮那一段（單點）
int idleColor[3] = { 0, 0, 60 };               // 待機顏色（淡藍）
int okColor[3]   = { 0, 255, 0 };              // 下單成功閃爍顏色（綠）

// ----- 功能開關 -----
bool useB     = false;                         // Step 2：選項 B
bool useOrder = false;                         // Step 3：確認燈＋下單鈕

// ===== 以下不用改 =====
int lastButton = LOW;
int orderCount = 0;

void setColor(int c[]) {
  analogWrite(pinR, c[0]);
  analogWrite(pinG, c[1]);
  analogWrite(pinB, c[2]);
}

void showLevel(int leds[], int count, int level) {
  for (int i = 0; i < count; i++) {
    bool on = fillMode ? (i <= level) : (i == level);
    digitalWrite(leds[i], on ? HIGH : LOW);
  }
}

void setup() {
  for (int i = 0; i < countA; i++) pinMode(ledA[i], OUTPUT);
  if (useB) for (int i = 0; i < countB; i++) pinMode(ledB[i], OUTPUT);
  if (useOrder) {
    pinMode(pinR, OUTPUT); pinMode(pinG, OUTPUT); pinMode(pinB, OUTPUT);
    pinMode(pinOrder, INPUT);
  }
  Serial.begin(9600);
}

void loop() {
  int a = map(analogRead(knobA), 0, 1024, 0, countA);
  showLevel(ledA, countA, a);

  int b = 0;
  if (useB) {
    b = map(analogRead(knobB), 0, 1024, 0, countB);
    showLevel(ledB, countB, b);
  }

  if (useOrder) {
    setColor(idleColor);
    int now = digitalRead(pinOrder);
    if (now == HIGH && lastButton == LOW) {
      delay(50);
      orderCount++;
      Serial.print("Order #");
      Serial.print(orderCount);
      Serial.print("  " + nameA + ": " + labelA[a]);
      if (useB) Serial.print("  " + nameB + ": " + labelB[b]);
      Serial.println();
      int off[3] = { 0, 0, 0 };
      for (int k = 0; k < 3; k++) {
        setColor(okColor); delay(150);
        setColor(off);     delay(150);
      }
    }
    lastButton = now;
  }
  delay(20);
}
```

| 區塊 | 要做什麼 |
| --- | --- |

| 參數區 | `labelA[]`、`labelB[]` 改成你分店菜單的文字（英文）；限制卡 C 的 `nameB` 改成 `"Temp"` |
| 功能開關 | Step 2 → `useB = true`；Step 3 → `useOrder = true` |

- 至少修改模板參數區的 **4 個參數**
- 至少 1 題「配線變化挑戰」：自己設計一個「不改程式、只改線」的客戶需求變更

**繳交內容**：

1. 情境說明（3～5 句）：客戶是誰、要解決什麼問題
2. 配線設計單
3. 參數修改表：改了哪些參數、為什麼
4. 你設計的配線變化挑戰與解答
5. Tinkercad 分享連結

## 配線除錯站

| 現象 | 先檢查這裡 | 修正方式 |
| --- | --- | --- |
| 旋鈕讀值一直是 0 或 1023，轉了不會變 | 旋鈕中間腳有沒有接到 A 腳？ | 中間腳接 A 腳，兩邊接 5V 與 GND |
| 旋鈕讀值亂跳 | 程式裡的 A 腳編號是否和實際接線一致 | 用工具 1 逐一確認 |
| 旋鈕方向跟需求相反 | 左右兩腳的 5V 與 GND | 把兩邊電源線對調，不用改程式 |
| 調光沒有漸變，只有全亮全滅 | 燈是不是接在 `~` 腳？是不是接在 A 腳？ | 改接到 3、5、6、9、10、11 |
| 長條燈或跑馬燈順序亂掉 | 陣列順序和麵包板擺放順序是否一致 | 用工具 2 確認，再調整陣列或線 |
| 程式無法上傳 | 腳位區是否還有 `?` 沒填 | 用到的填腳位，沒接的填 `-1` |
| 按鈕按了沒反應 | 功能開關是否已改成 `true`？按鈕是否有 10kΩ？ | 打開功能開關，照第 2 週接法檢查 |
| Serial Monitor 的菜單文字是空白 | `labelA[]`、`labelB[]` 的段數是否和 `countA`、`countB` 一致 | 有幾段就填幾個文字 |
| 兩個元件互相干擾 | 腳位規劃表上是否有兩個元件填了同一隻腳 | 一隻腳只接一個元件 |

## 反思與延伸討論

1. 本週四個程式模板，被套用到十個不同的情境（會議室、輸送帶、倉庫、手搖飲、電風扇、閱讀燈、跑步機、鍋爐、冷氣……）。這說明了什麼？未來你在職場上看到一個新設備時，可以怎麼拆解它的「輸入」和「輸出」？
2. 「配線變化挑戰」要求你不改程式、只改線。在真實的產品維護中，「改硬體」和「改軟體」各有什麼成本和風險？什麼情況下應該選哪一種？
3. 每組的客戶限制卡不同，答案也不同。真實的顧問工作中，「客戶的特殊條件」常常是專案最花時間的地方。你會怎麼在專案一開始就把這些條件問清楚？
