# 第 8 週：期中專題 — 智慧場域整合提案

## 主題專案：從客戶需求到可驗收的系統

> 🎯 **本週定位**：本週**沒有新元件、沒有新語法**。你們的顧問團隊要承接一個完整的客戶案，把前七週學過的元件整合成一套「智慧場域監控站」。
>
> 和第 4～7 週一樣，**每一組會抽到不同的客戶限制卡**，同一個案例在不同組會配出不同的電路。三個功能模組直接**套用第 5～7 週的程式模板**（T6、T11、T15），整合版則使用本週提供的整合程式——**你們的功夫在規劃、配線、驗收與提案**：
>
> 1. **需求分析與規格訂定**：溫度幾度算危險？可以容納幾人？燈多暗要開？
> 2. **腳位總規劃**：全學期最多元件的一次，再加上限制卡，`~` 腳怎麼分？
> 3. **分模組建置**：每個模組照五個固定環節各自完成、各自驗收
> 4. **整合與安全優先權**：功能衝突時，誰說了算？
> 5. **現場配線變化**：老師在整合後現場出題，只能改線應變
> 6. **驗收測試與提案簡報**：證明系統可靠，說服客戶買單
>
> 🏁 **期中成果**：每組繳交 **4 個 Tinkercad 檔案**（3 個功能模組＋1 個整合系統）、1 份規劃書、1 份驗收測試報告，並進行 5 分鐘提案簡報。

## 專題簡報：選擇你的客戶

> 📖 **情境**：顧問公司七週來接了 20 多個小案子，口碑傳開了。這次有三家客戶同時來詢問「整合型」的大案子。每組選一家客戶（或自訂），組成 3～4 人的顧問團隊承接。

三家客戶的需求骨架相同，都由**照明、溫度安全、出入管制、緊急停止**四大功能組成，只是規格不同：

| 功能 | 案例 A：社區便利商店 | 案例 B：冷鏈倉儲中心 | 案例 C：溫室農場參觀園區 |
| --- | --- | --- | --- |
| **照明** | 天黑時招牌燈自動亮，越暗越亮 | 倉庫天黑時照明自動亮 | 陰天或傍晚補光燈自動亮 |
| **溫度安全** | 冷藏櫃溫度監控 | 冷藏區溫度監控 | 溫室溫度監控 |
| ─ 警戒線 | 7°C | 6°C | 32°C |
| ─ 危險線 | 10°C | 8°C | 38°C |
| **出入管制** | 自動門（入口光柵感應），店內人數上限 | 冷藏區門禁閘門，同時進入人數上限 | 參觀步道閘門，園區人數上限 |
| ─ 人數上限 | 8 人 | 3 人 | 10 人 |
| **緊急停止** | 店員急停鈕 | 倉管急停鈕 | 園區管理員急停鈕 |
| **溫度危險時的連鎖** | 自動門鎖住不開（避免冷氣外洩） | 門禁鎖住（避免人員進入異常區域） | 步道閘門鎖住（避免遊客進入過熱溫室） |

> **案例 D：自訂客戶**
> 自己找一個需要這四大功能的場域（例如：自習室、健身房、社區活動中心）。須在 M0 提出規格表，經老師同意後才能開始。

## 🃏 小組客戶限制卡

每一組依**組別編號**抽一張限制卡。限制卡會影響**整個系統**的腳位規劃，所以同一個案例在不同組會配出不同的電路。

| 組別編號 | 抽到 |
| --- | --- |
| 1、5、9 | 限制卡 A |
| 2、6、10 | 限制卡 B |
| 3、7、11 | 限制卡 C |
| 4、8、12 | 限制卡 D |

| 限制卡 | 現場條件 | 主要影響 |
| --- | --- | --- |
| **A：舊系統佔腳** | 客戶現場的舊監視系統已佔用 **~5**；舊系統的線材還佔了 **Pin 13** | 照明燈只剩一隻 `~` 腳可選 |
| **B：雙燈照明** | 照明有 **2 盞**（店內、店外），必須同步、**只能用 1 隻腳**；急停鈕必須接 **A4**（裝在牆面控制箱） | 兩燈共腳；A 腳分配 |
| **C：雙開門＋單色燈** | 出入口是**雙開門**（兩顆伺服同步，只能用 1 隻腳）；客戶指定狀態燈用**紅、綠、黃三顆單色燈**，不用 RGB | 伺服共用訊號線；用參數把三顆單色燈「當成」RGB |
| **D：腳位吃緊＋暗室入口** | **Pin 2～4** 被收銀系統佔用；入口光柵裝在**暗處**，平常是暗的，有人帶光（手機、手電筒）進入才觸發 | 借用 A 腳；入口光柵觸發方向 |

> 💡 限制卡 C 的訣竅：整合程式的狀態燈顏色都寫在參數區，每個顏色是 **R、G、B 三個開關（1 亮、0 滅）**。把紅燈接在 `pinR`、綠燈接在 `pinG`、黃燈接在 `pinB`，再把「黃色狀態」的參數改成 `{0, 0, 1}`，就能用三顆單色燈表達所有狀態。

## 里程碑 1：照明模組（套用 T6）

### 📖 模組需求

環境變暗時，照明燈自動亮起，**越暗越亮**；現場人員用旋鈕調整「多暗才開始亮」。

### ✏️ 接線前決策題

1. 這個模組要用到 T6 的哪些功能？哪些功能開關要開、哪些不用？
2. 照明燈要接在哪一隻 `~` 腳？為什麼？（考慮整個系統未來會有伺服＋蜂鳴器）
3. 限制卡 B：兩盞照明燈要怎麼接？
4. 環境光敏電阻要裝在真實現場的哪裡？如果裝在照明燈旁邊會怎樣？

### 🔌 接線任務

1. 照**腳位總表**接上：環境光敏電阻（配 10kΩ）、旋鈕、照明燈（各串 220Ω）。
2. ✅ 檢查：類比讀值檢查器（光敏電阻最亮最暗、旋鈕 0～1023）、接線驗證器（照明燈）。

### 💻 套用 T6（從第 5 週講義複製）

| 參數 | 要改成 | 說明 |
| --- | --- | --- |
| `pinLDR`、`pinKnob`、`pinLamp` | 依腳位總表 | `lowLine` 不用改，接了旋鈕就由旋鈕決定 |
| `pinR`、`pinG`、`pinB`、`pinBuzzer` | `-1` | 這個模組不用 |
| `lampWhenLow` | `true` | 變暗才開燈 |
| `dimLamp` | `true` | 越暗越亮 |

## 里程碑 4：系統整合與安全優先權

### 整合步驟

1. **另存新檔**：從 M3 的檔案另存為 `MID-M4-組別`。
2. **合併電路**：把 M1、M2 的元件照原腳位搬到同一塊麵包板，再加上**急停鈕**。
3. **全面體檢**：用各元件的測試工具逐一確認。
4. **上傳整合程式**：填好腳位區與參數區，依序打開四個功能開關，每開一個就測一次。

### 優先權：功能衝突時，誰說了算？

```
每一輪 loop 依序檢查：
  ① 急停中？        → 閘門關閉並停止回應，只保留照明，後面全部跳過
  ② 溫度危險鎖定？  → 閘門鎖住（安全連鎖），照明照常運作
  ③ 照明控制        → 依光線調整
  ④ 出入管制        → 只有在 ①② 都沒事時才會執行
  ⑤ 總狀態燈        → 依燈號定義表顯示最優先的狀況
```

> 🤔 **急停時照明要不要關？** 本程式選擇「急停時照明保持運作」——緊急狀況下人員需要看得見才能疏散。你的客戶情境也是這樣嗎？請在規劃書說明。

### 期中整合程式（只改腳位區、參數區、功能開關）

```cpp
// ===== 期中整合程式：智慧場域監控站 =====
#include <Servo.h>

// ----- 腳位區（照 M0 腳位總表；沒接的填 -1）-----
int pinKnob    = A0;                // M1 照明門檻旋鈕
int pinLDR     = A1;                // M1 環境光敏電阻
int pinTemp    = A2;                // M2 TMP36
int pinGateLDR = A3;                // M3 入口光敏電阻
int pinLamp    = ?;                 // M1 照明燈（~ 腳）
int pinR = ?, pinG = ?, pinB = ?;   // M2 狀態燈（RGB 或三顆單色燈）
int pinBuzzer  = ?;                 // M2 蜂鳴器
int pinServo   = ?;                 // M3 閘門伺服
int btnReset   = ?;                 // M2 復歸鈕
int btnExit    = ?;                 // M3 離場鈕
int btnEStop   = ?;                 // M4 急停鈕

// ----- 參數區：客戶規格 -----
float warnLine   = 30.0;            // 溫度警戒線
float dangerLine = 35.0;            // 溫度危險線
int capacity     = 5;               // 人數上限
int gateThreshold = 300;            // 入口光柵門檻
bool gateTriggerDark = true;        // true：被擋住（變暗）觸發；false：變亮觸發
int closedAngle  = 0;               // 閘門關閉角度
int openAngle    = 90;              // 閘門開啟角度
int holdTime     = 2000;            // 閘門開啟時間（毫秒）

// ----- 參數區：狀態燈顏色（R, G, B 開關：1 亮、0 滅）-----
int colorOK[3]     = { 0, 1, 0 };   // 一切正常（綠）
int colorWarn[3]   = { 1, 1, 0 };   // 溫度警戒（黃）
int colorDanger[3] = { 1, 0, 0 };   // 溫度危險（紅）
int colorFull[3]   = { 1, 0, 1 };   // 人數已滿（紫）
int colorEStop[3]  = { 1, 0, 0 };   // 急停（閃爍）

// ----- 功能開關：逐一打開測試 -----
bool useLighting = false;           // M1
bool useTemp     = false;           // M2
bool useGate     = false;           // M3
bool useEStop    = false;           // M4

// ===== 以下不用改 =====
Servo gate;
bool eStopped = false, tempLocked = false, wasGateTrig = false;
int inside = 0, tick = 0;
int lastExit = LOW, lastReset = LOW, lastEStop = LOW;

float readC(int pin) {
  float voltage = analogRead(pin) * 5.0 / 1023.0;
  return (voltage - 0.5) * 100.0;
}

void setColor(int c[]) {
  digitalWrite(pinR, c[0] ? HIGH : LOW);
  digitalWrite(pinG, c[1] ? HIGH : LOW);
  digitalWrite(pinB, c[2] ? HIGH : LOW);
}

void lightsOff() {
  digitalWrite(pinR, LOW);
  digitalWrite(pinG, LOW);
  digitalWrite(pinB, LOW);
}

void sweepTo(int from, int to) {
  int step = (to > from) ? 1 : -1;
  for (int a = from; a != to; a += step) { gate.write(a); delay(8); }
  gate.write(to);
}

bool pressed(int pin, int &last) {
  if (pin < 0) return false;
  int now = digitalRead(pin);
  bool edge = (now == HIGH && last == LOW);
  last = now;
  if (edge) delay(50);
  return edge;
}

void handleLighting() {
  int light = analogRead(pinLDR);
  int threshold = analogRead(pinKnob);
  int lamp = 0;
  if (light < threshold) lamp = constrain(map(light, 0, threshold, 255, 30), 30, 255);
  analogWrite(pinLamp, lamp);
}

void setup() {
  gate.attach(pinServo);
  gate.write(closedAngle);
  pinMode(pinLamp, OUTPUT);
  pinMode(pinR, OUTPUT); pinMode(pinG, OUTPUT); pinMode(pinB, OUTPUT);
  pinMode(btnReset, INPUT);
  pinMode(btnExit, INPUT);
  if (btnEStop >= 0) pinMode(btnEStop, INPUT);
  Serial.begin(9600);
  Serial.println("=== Smart Site Monitor READY ===");
}

void loop() {
  tick++;
  bool exitHit  = pressed(btnExit, lastExit);
  bool resetHit = pressed(btnReset, lastReset);
  bool eStopHit = useEStop && pressed(btnEStop, lastEStop);
  float t = readC(pinTemp);

  // ===== ① 急停：最高優先 =====
  if (useEStop) {
    if (eStopHit && !eStopped) {
      eStopped = true;
      gate.write(closedAngle);
      Serial.println("!!! EMERGENCY STOP !!!");
    }
    if (eStopped) {
      if (resetHit) {
        eStopped = false;
        resetHit = false;                         // 這一按只用來解除急停
        noTone(pinBuzzer);
        Serial.println("E-STOP released by reset");
      } else {
        if (useLighting) handleLighting();       // 急停時照明保持運作
        if ((tick / 10) % 2) setColor(colorEStop); else lightsOff();
        if (tick % 20 == 0) tone(pinBuzzer, 400, 150);
        delay(30);
        return;                                   // 後面全部跳過
      }
    }
  }

  // ===== ② 溫度安全 =====
  int tempLevel = 0;
  if (useTemp) {
    if (t >= dangerLine)    tempLevel = 2;
    else if (t >= warnLine) tempLevel = 1;
    if (tempLevel == 2 && !tempLocked) {
      tempLocked = true;
      Serial.println("TEMP DANGER - LOCKED, gate disabled");
    }
    if (resetHit && tempLocked) {
      if (tempLevel < 2) { tempLocked = false; noTone(pinBuzzer); Serial.println("Temp lock RESET"); }
      else Serial.println("Cannot reset: still too hot");
    }
  }

  // ===== ③ 照明 =====
  if (useLighting) handleLighting();

  // ===== ④ 出入管制（溫度鎖定時不執行：安全連鎖） =====
  if (useGate) {
    int light = analogRead(pinGateLDR);
    bool trig = gateTriggerDark ? (light < gateThreshold) : (light > gateThreshold);
    bool entering = trig && !wasGateTrig;
    wasGateTrig = trig;

    if (entering && tempLocked) {
      Serial.println("Gate LOCKED by temperature interlock");
    } else if (entering && inside >= capacity) {
      tone(pinBuzzer, 300, 600);
      Serial.println("FULL - entry refused");
    } else if (entering) {
      inside++;
      tone(pinBuzzer, 1200, 100);
      Serial.print("Enter. Inside: ");
      Serial.println(inside);
      sweepTo(closedAngle, openAngle);
      delay(holdTime);
      sweepTo(openAngle, closedAngle);
    }
    if (exitHit && !tempLocked) {
      if (inside > 0) inside--;
      Serial.print("Exit. Inside: ");
      Serial.println(inside);
    }
  }

  // ===== ⑤ 總狀態燈（依燈號定義表的優先順序） =====
  if (tempLocked) {
    setColor(colorDanger);
    tone(pinBuzzer, 2000);
  } else if (tempLevel == 1) {
    setColor(colorWarn);
    if (tick % 30 == 0) tone(pinBuzzer, 1000, 80);
  } else if (useGate && inside >= capacity) {
    setColor(colorFull);
  } else {
    setColor(colorOK);
  }

  if (tick % 30 == 0) {
    Serial.print("Temp: ");
    Serial.print(t);
    Serial.print(" C   Inside: ");
    Serial.print(inside);
    Serial.print("/");
    Serial.println(capacity);
  }
  delay(30);
}
```

**本里程碑要改的地方**：

| 區塊 | 要做什麼 |
| --- | --- |
| 腳位區 | 依 M0 腳位總表填入（限制卡 B 的急停鈕寫 `A4`） |
| 參數區：客戶規格 | 依規格表；限制卡 D 的 `gateTriggerDark` 依你在 M3 的決定 |
| 參數區：狀態燈顏色 | 依燈號定義表；限制卡 C 改成三顆單色燈的開關組合 |
| 功能開關 | 依序打開 `useLighting` → `useTemp` → `useGate` → `useEStop`，每開一個就測一次 |

| 2. 系統展示 | 2 分鐘 | Tinkercad 現場操作：正常情境 → 異常情境 → 急停 |
| 3. 現場條件與應變 | 1 分鐘 | 我們抽到什麼限制卡？怎麼配線克服？現場配線變化怎麼應變？ |
| 4. 安全與擴充 | 1 分鐘 | 有哪些安全連鎖？還剩幾隻腳可擴充？ |

**簡報規則**：

- 不准講程式碼。客戶在乎「店員按這顆鈕會發生什麼事」。
- 每個技術名詞都要翻成客戶聽得懂的話。例如「安全連鎖」→「冷藏櫃壞掉時，自動門會自動鎖住，避免冷氣外洩」。

## 配線除錯站

| 現象 | 先檢查這裡 | 修正方式 |
| --- | --- | --- |
| M1～M3 各自正常，合併後某個功能失效 | 兩個模組是否用了同一隻腳 | 對照 M0 腳位總表 |
| 照明燈只有全亮全滅 | 是否接在 9、10（伺服借走）或 3、11（蜂鳴器借走）、或被限制卡佔用 | 改接還能調光的 `~` 腳 |
| 拖曳環境光線時，閘門卻打開了 | 兩顆光敏電阻的 A 腳是否接反 | 用類比讀值檢查器逐一確認 |
| 急停後系統「卡住」不動 | 這是正確設計 | 按復歸鈕解除 |
| 溫度鎖定後閘門還能開 | `useTemp` 是否打開 | 開啟功能開關後重測 |
| 限制卡 C 的三顆單色燈亮錯 | 燈接的腳位和顏色參數是否對應 | 對照燈號定義表 |
| 合併後感測器讀值亂跳 | 電源軌是否斷開 | 檢查 5V、GND 是否全部連通 |
| 程式無法上傳 | 腳位區是否還有 `?` 沒填 | 填完所有腳位 |

## 反思與延伸討論

1. 本專題先分三個模組各自完成，再整合。如果一開始就把所有元件接在一起，會遇到什麼困難？這和專案管理中的「工作分解結構（WBS）」有什麼關係？
2. 三個模組直接套用第 5～7 週的模板，整合程式也只改參數。同一個案例、不同限制卡的組別，最後配出的電路卻都不一樣。這說明了「標準化」和「客製化」之間的什麼關係？
3. 「現場配線變化挑戰」要在 10 分鐘內只靠改線完成。真實專案中，客戶在驗收前臨時改需求時，顧問團隊應該怎麼評估「這個變更要不要接」？
4. 為什麼要主動做 QA 測試，而不是等客戶用了再修？請從成本、商譽、安全三個角度說明。

**各限制卡的關鍵差異**：

| 限制卡 | 審查重點 |
| --- | --- |
| A | ~5 被佔用 → 照明燈只能接 **~6**；Pin 13 不可用 |
| B | 兩盞照明燈各自串 220Ω、接同一隻 `~` 腳；急停鈕在 A4（`btnEStop = A4`） |
| C | 兩顆伺服橘線接同一隻腳；三顆單色燈接 R/G/B 腳位，`colorWarn` 改成 `{0,0,1}`、`colorFull` 需重新定義（例如紅＋黃 `{1,0,1}`） |
| D | Pin 2～4 不可用 → 13 隻元件腳要放進 Pin 5～13（9 隻）＋A4、A5，按鈕或蜂鳴器需借 A 腳；`gateTriggerDark = false` 或光敏電阻反相接法 |

**共同審查重點**：

- 照明燈是否接在還能調光的 `~` 腳（最常見錯誤：接在 9 或 10）
- 學生是否能說明狀態燈為什麼不需要 `~` 腳
- 兩顆光敏電阻是否分區擺放、A 腳不混淆
