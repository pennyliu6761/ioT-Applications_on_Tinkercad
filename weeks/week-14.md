## 電路體檢站（3 分鐘快速複習）

**體檢題 1**：回想第 10 週學過的 L293D 馬達驅動晶片——那也是一種「用 Arduino 的小訊號，控制超出 Arduino 直接驅動能力的大功率裝置」的元件。繼電器的概念完全相同，只是繼電器控制的通常是「開/關」這種簡單的二元狀態負載（如燈泡、電熱器），而不像馬達驅動晶片需要處理方向與轉速這麼複雜的控制。

**體檢題 2**：PIR 感測器讀取方式其實跟第 2 週學過的按鈕非常類似——都是用 `digitalRead()` 判斷「HIGH 代表偵測到、LOW 代表沒偵測到」，只是訊號來源從「手指按壓」變成「紅外線變化」。這提醒我們：這學期學過的「讀取數位訊號」的程式邏輯，可以套用在各種完全不同的感測原理上，程式碼的寫法幾乎不用改變。

**體檢題 3**：類比搖桿跟第 4 週學過的可變電阻有什麼異同？
> 答案：搖桿內部其實就是「兩顆獨立的可變電阻」組合而成——一顆負責偵測水平方向（X 軸），一顆負責偵測垂直方向（Y 軸）。所以讀取搖桿的方式跟讀取旋鈕完全相同（都是 `analogRead()`），只是這次需要同時讀取兩個腳位的數值。

## 模擬設計專案配置

### 元件清單
| 元件 | 數量 | 說明 |
|---|---|---|
| Arduino Uno R3 | 1 | 主控板 |
| Breadboard | 1 | 電路佈局 |
| Relay Module（繼電器模組） | 1 | 大負載切換核心元件 |
| LED | 1 | 模擬繼電器控制的負載（如燈泡） |
| 220Ω 電阻 | 1 | LED 限流電阻 |
| PIR Motion Sensor | 1 | 人體動作偵測 |
| Joystick（類比搖桿） | 1 | 手動操作輸入裝置 |
| Pushbutton | 1 | 模式切換鈕（自動/手動） |
| 10kΩ 電阻 | 1 | 按鈕下拉電阻 |
| RGB LED（共陰極） | 1 | 系統狀態指示燈 |
| 220Ω 電阻 | 3 | RGB 三色限流電阻 |

### 接線步驟

**Part A：繼電器模組**
1. 拖曳一顆 **Relay Module** 到工作區，模組通常有：VCC、GND、IN（訊號控制腳），以及負載端的 COM、NO、NC 三個接點。
2. VCC 接 **5V**，GND 接 **GND**，IN 接 Arduino **Pin 7**。
3. 負載端：用 LED（模擬燈泡）串接電阻，一端接繼電器的 **COM**，另一端接繼電器的 **NO（常開接點）**，並接上獨立的電源迴路（COM 端另一側接 5V 或依 Tinkercad 元件實際接法為準）。

> 💡 **繼電器工作原理小整理**：繼電器內部是一個小型電磁鐵，通電時會吸引一個機械開關動作，讓「COM」與「NO」兩點導通（原本是斷開的）。這代表 Arduino 只需要送出微小的訊號電流「啟動電磁鐵」，就能控制另一個完全獨立、電壓電流可能大得多的負載迴路，兩個迴路彼此電氣隔離，這是繼電器最重要的安全特性。

**Part B：PIR 動作感測器**
1. 拖曳一顆 **PIR Motion Sensor** 到工作區，VCC 接 **5V**，GND 接 **GND**，訊號腳接 Arduino **Pin 2**。

**Part C：類比搖桿**
1. 拖曳一顆 **Joystick** 到工作區，VCC 接 **5V**，GND 接 **GND**。
2. X 軸訊號腳接 Arduino **A0**，Y 軸訊號腳接 Arduino **A1**。
3. 如果搖桿有按壓開關功能（按下搖桿本身），該腳位可接 **Pin 8**（本週選用功能，非必要）。

**Part D：模式切換按鈕與 RGB LED**
1. 按鈕沿用第 2 週接法：下拉電阻 + 訊號線接 **Pin 4**。
2. RGB LED 沿用第 3 週接法：R → ~9、G → ~10、B → ~11。

### 腳位對照表（本週共用）
| 元件 | 腳位 |
|---|---|
| 繼電器 IN | Pin 7 |
| PIR 訊號腳 | Pin 2 |
| 搖桿 X 軸 | A0 |
| 搖桿 Y 軸 | A1 |
| 模式切換按鈕 | Pin 4 |
| RGB LED - R / G / B | ~9 / ~10 / ~11 |

> 💡 **配置檢查清單**
> - [ ] 繼電器模組的 VCC、GND、IN 正確接線，負載迴路正確接到 COM/NO
> - [ ] PIR 感測器正確接線
> - [ ] 搖桿的 X、Y 軸分別接到 A0、A1
> - [ ] 模式切換按鈕與 RGB LED 均已正確接線

## 後端程式設計：五道機關關卡

### 關卡 1：繼電器基礎 — 用小訊號切換大負載

**機關故事**：在做出任何自動化邏輯前，你得先確認繼電器真的能被 Arduino 控制切換。

#### 範例 1-1：繼電器基礎開關測試
```cpp
// ============================================
// 範例 1-1：繼電器基礎控制 - 開啟與關閉負載
// ============================================

int pinRelay = 7;

void setup() {
  pinMode(pinRelay, OUTPUT);
}

void loop() {
  digitalWrite(pinRelay, HIGH);   // 啟動繼電器，負載迴路導通（例如燈泡點亮）
  delay(1000);
  digitalWrite(pinRelay, LOW);    // 關閉繼電器，負載迴路斷開
  delay(1000);
}
```
**教學重點**：從程式碼的角度來看，控制繼電器跟控制 LED 幾乎一模一樣（都是 `digitalWrite`），但背後代表的意義完全不同——這個 HIGH/LOW 訊號控制的不是幾毫安培的 LED 電流，而是可能高達好幾安培的真實負載（如馬達、燈具、加熱器）。這正是繼電器「以小控大」的核心價值。

#### 範例 1-2：把繼電器控制封裝成語意清楚的函式
```cpp
// ============================================
// 範例 1-2：封裝成 turnOnLoad() / turnOffLoad()，讓程式碼語意更清楚
// ============================================

int pinRelay = 7;

void turnOnLoad() {
  digitalWrite(pinRelay, HIGH);
}

void turnOffLoad() {
  digitalWrite(pinRelay, LOW);
}

void setup() {
  pinMode(pinRelay, OUTPUT);
}

void loop() {
  turnOnLoad();
  delay(1000);
  turnOffLoad();
  delay(1000);
}
```

#### 範例 1-3：按鈕控制繼電器開關
```cpp
// ============================================
// 範例 1-3：按鈕切換繼電器負載開關（Toggle 邏輯，複習第 2 週）
// ============================================

int pinRelay = 7;
int pinButton = 4;
int lastButtonState = LOW;
bool loadOn = false;

void setup() {
  pinMode(pinRelay, OUTPUT);
  pinMode(pinButton, INPUT);
}

void loop() {
  int currentState = digitalRead(pinButton);

  if (currentState == HIGH && lastButtonState == LOW) {
    delay(50);
    loadOn = !loadOn;
    digitalWrite(pinRelay, loadOn ? HIGH : LOW);
  }
  lastButtonState = currentState;
}
```

### 關卡 2：PIR 動作感測 — 自動觸發邏輯

**機關故事**：智慧控制室需要能自動偵測有沒有人靠近，這一關我們學習讀取 PIR 感測器並觸發對應動作。

#### 範例 2-1：讀取 PIR 感測器狀態
```cpp
// ============================================
// 範例 2-1：讀取 PIR 感測器 - 有偵測到動作時印出訊息
// ============================================

int pinPIR = 2;

void setup() {
  pinMode(pinPIR, INPUT);
  Serial.begin(9600);
}

void loop() {
  int motionDetected = digitalRead(pinPIR);

  if (motionDetected == HIGH) {
    Serial.println("偵測到動作！");
  } else {
    Serial.println("無動作");
  }
  delay(300);
}
```

#### 範例 2-2：PIR 觸發繼電器自動照明
```cpp
// ============================================
// 範例 2-2：偵測到動作，自動開啟負載（模擬自動感應燈）
// ============================================

int pinPIR = 2;
int pinRelay = 7;

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
}

void loop() {
  int motionDetected = digitalRead(pinPIR);
  digitalWrite(pinRelay, motionDetected);   // 直接把讀到的狀態當作輸出值（複習第 2 週學過的技巧）
}
```

#### 範例 2-3：延遲熄滅（避免動作停止就立刻關燈）
```cpp
// ============================================
// 範例 2-3：偵測到動作後維持開啟一段時間，即使動作停止也不會立刻關閉
// 情境：真實感應燈通常有「維持時間」設計，避免使用者站著不動時燈突然熄滅
// ============================================

int pinPIR = 2;
int pinRelay = 7;
unsigned long lastMotionTime = 0;
long holdDuration = 3000;   // 動作停止後，維持開啟 3 秒

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
}

void loop() {
  int motionDetected = digitalRead(pinPIR);

  if (motionDetected == HIGH) {
    lastMotionTime = millis();   // 每次偵測到動作，更新「最後偵測到的時間」
  }

  // 只要距離「最後一次偵測到動作」還在維持時間內，就保持開啟
  if (millis() - lastMotionTime < holdDuration) {
    digitalWrite(pinRelay, HIGH);
  } else {
    digitalWrite(pinRelay, LOW);
  }
}
```
**新語法預告提醒**：這裡第一次正式使用 `millis()` 進行非阻塞式計時（第 8 週期中專題曾經簡單提過一次），這是判斷「距離某個事件過了多久」最實用的手法，不需要用 `delay()` 卡住整個程式。這個技巧會在第 15～16 週的期末整合專題中大量派上用場。

### 關卡 3：類比搖桿 — 雙軸輸入基礎

**機關故事**：操作員需要一個直覺的手動控制裝置，這一關我們學習讀取搖桿的雙軸數值。

#### 範例 3-1：讀取搖桿 X、Y 軸數值
```cpp
// ============================================
// 範例 3-1：讀取搖桿的水平（X）與垂直（Y）數值
// ============================================

int pinX = A0;
int pinY = A1;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int xValue = analogRead(pinX);
  int yValue = analogRead(pinY);

  Serial.print("X: ");
  Serial.print(xValue);
  Serial.print("  Y: ");
  Serial.println(yValue);
  delay(200);
}
```
**操作提醒**：搖桿放開時通常會回到「中間位置」，數值大約落在 512 附近（0~1023 的中點），往任一方向推動時數值會偏向 0 或 1023 兩端，這跟旋鈕「轉到底才是極值」的特性不同，搖桿的「中心點」本身就有特殊意義（代表「無操作」）。

#### 範例 3-2：判斷搖桿推動方向
```cpp
// ============================================
// 範例 3-2：依據 X 軸數值判斷「左、中、右」三種方向
// ============================================

int pinX = A0;

void setup() {
  Serial.begin(9600);
}

void loop() {
  int xValue = analogRead(pinX);

  if (xValue < 400) {
    Serial.println("方向: 左");
  } else if (xValue > 600) {
    Serial.println("方向: 右");
  } else {
    Serial.println("方向: 中間（無操作）");
  }
  delay(200);
}
```

#### 範例 3-3：搖桿控制 RGB LED 顏色（X 控紅、Y 控藍）
```cpp
// ============================================
// 範例 3-3：搖桿兩軸分別控制不同顏色分量
// ============================================

int pinX = A0;
int pinY = A1;
int pinR = 9, pinG = 10, pinB = 11;

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
}

void loop() {
  int xValue = analogRead(pinX);
  int yValue = analogRead(pinY);

  int red = map(xValue, 0, 1023, 0, 255);
  int blue = map(yValue, 0, 1023, 0, 255);

  setColor(red, 0, blue);
}
```

### 關卡 4：自動與手動模式切換

**機關故事**：真正的控制台需要能在「自動感應」與「人工手動」兩種模式之間切換，這正是本週的核心主題。

#### 範例 4-1：按鈕切換自動/手動模式
```cpp
// ============================================
// 範例 4-1：按鈕切換系統運作模式
// ============================================

int pinButton = 4;
int lastButtonState = LOW;
bool manualMode = false;   // false = 自動模式, true = 手動模式

void setup() {
  pinMode(pinButton, INPUT);
  Serial.begin(9600);
}

void loop() {
  int currentState = digitalRead(pinButton);

  if (currentState == HIGH && lastButtonState == LOW) {
    delay(50);
    manualMode = !manualMode;
    Serial.println(manualMode ? "切換到：手動模式" : "切換到：自動模式");
  }
  lastButtonState = currentState;
}
```

#### 範例 4-2：自動模式用 PIR，手動模式用搖桿

// ============================================
// 範例 4-2：兩種模式各自控制不同的輸出邏輯
// ============================================

int pinPIR = 2;
int pinRelay = 7;
int pinX = A0;
int pinButton = 4;
int lastButtonState = LOW;

  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
  pinMode(pinButton, INPUT);
}

void loop() {
  int currentState = digitalRead(pinButton);
  if (currentState == HIGH && lastButtonState == LOW) {
    delay(50);
    manualMode = !manualMode;
  }
  lastButtonState = currentState;

  if (manualMode) {
    // 手動模式：搖桿推到右側就開啟負載

    digitalWrite(pinRelay, xValue > 600 ? HIGH : LOW);
  } else {
    // 自動模式：PIR 偵測到動作就開啟負載
    digitalWrite(pinRelay, digitalRead(pinPIR));
  }
}

### 關卡 5：手動優先權設計

**機關故事**：真實工業控制盤的黃金原則——**不管自動系統正在做什麼，只要操作員手動介入，永遠優先執行人工指令**。這是這學期最後一次探討「優先權設計」，也是最貼近真實工業安全理念的一次。

#### 範例 5-1：搖桿按壓觸發「緊急手動接管」
```cpp
// ============================================
// 範例 5-1：不論目前在自動還是手動模式，搖桿被按下就立刻強制切到手動
// ============================================

int pinPIR = 2;
int pinRelay = 7;
int pinX = A0;
int pinJoystickButton = 8;
bool manualMode = false;

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
  pinMode(pinJoystickButton, INPUT);
}

void loop() {
  // 最高優先權：搖桿按下的瞬間，強制進入手動模式
  if (digitalRead(pinJoystickButton) == HIGH) {
    manualMode = true;
  }

  if (manualMode) {
    int xValue = analogRead(pinX);
    digitalWrite(pinRelay, xValue > 600 ? HIGH : LOW);
  } else {
    digitalWrite(pinRelay, digitalRead(pinPIR));
  }
}
```

#### 範例 5-2：搖桿任何移動都視為「手動介入」
```cpp
// ============================================
// 範例 5-2：更貼近真實情境 - 搖桿只要偏離中心，就自動接管為手動模式
// ============================================

int pinPIR = 2;
int pinRelay = 7;
int pinX = A0;
bool manualMode = false;

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
}

void loop() {
  int xValue = analogRead(pinX);

  // 只要搖桿明顯偏離中心（不在 400~600 這個「無操作」範圍內），視為操作員介入
  if (xValue < 400 || xValue > 600) {
    manualMode = true;
  }

  if (manualMode) {
    digitalWrite(pinRelay, xValue > 600 ? HIGH : LOW);
  } else {
    digitalWrite(pinRelay, digitalRead(pinPIR));
  }
}
```
**思考問題**：範例 5-2 一旦 `manualMode` 變成 `true`，程式碼中沒有任何地方讓它變回 `false`，代表系統會永遠停留在手動模式。這是否合理？如果要讓系統在操作員放開搖桿一段時間後「自動恢復」到自動模式，你會怎麼修改（提示：可以參考關卡 2 範例 2-3 用過的 `millis()` 計時手法）？

### 🏆 BOSS 關：智慧感應與操作台主控系統

**機關故事**：整合本週所有技巧，打造完整的總控制室系統——自動 PIR 感應、手動搖桿操作、手動優先權、一段時間無操作自動恢復自動模式。

```cpp
// ============================================
// BOSS 關：智慧感應與操作台主控系統 - 整合本週所有技巧
// 功能：PIR自動感應 + 搖桿手動操作 + 手動優先權 + 逾時自動恢復
// ============================================

int pinPIR = 2;
int pinRelay = 7;
int pinX = A0;
int pinR = 9, pinG = 10, pinB = 11;

bool manualMode = false;
unsigned long lastManualActionTime = 0;
long manualTimeout = 5000;   // 手動操作 5 秒無動作，自動恢復自動模式

void setColor(int r, int g, int b) {
  analogWrite(pinR, r);
  analogWrite(pinG, g);
  analogWrite(pinB, b);
}

void setup() {
  pinMode(pinPIR, INPUT);
  pinMode(pinRelay, OUTPUT);
  pinMode(pinR, OUTPUT);
  pinMode(pinG, OUTPUT);
  pinMode(pinB, OUTPUT);
  Serial.begin(9600);
  Serial.println("=== 智慧感應與操作台系統啟動（自動模式）===");
}

void loop() {
  int xValue = analogRead(pinX);
  bool joystickActive = (xValue < 400 || xValue > 600);

  // --- 最高優先權：搖桿有動作，立刻（或持續）進入手動模式 ---
  if (joystickActive) {
    if (!manualMode) {
      Serial.println(">>> 偵測到操作員介入，切換為手動模式 <<<");
    }
    manualMode = true;
    lastManualActionTime = millis();
  }

  // --- 逾時自動恢復：手動模式下，如果已經一段時間沒有新的搖桿動作，恢復自動模式 ---
  if (manualMode && !joystickActive) {
    if (millis() - lastManualActionTime > manualTimeout) {
      manualMode = false;
      Serial.println(">>> 操作員逾時無動作，自動恢復為自動模式 <<<");
    }
  }

  // --- 依模式執行對應邏輯 ---
  if (manualMode) {
    setColor(0, 0, 255);   // 藍色：手動模式
    digitalWrite(pinRelay, xValue > 600 ? HIGH : LOW);
  } else {
    setColor(0, 255, 0);   // 綠色：自動模式
    digitalWrite(pinRelay, digitalRead(pinPIR));
  }
}
```
**教學重點**：這是整個 Arduino 課程「優先權設計」主題的集大成之作——手動操作享有絕對優先權（第一段 `if`），但系統又貼心地設計了「操作員閒置一段時間後自動歸還控制權給自動系統」的邏輯，這種細膩的雙向切換設計，正是真實工業人機介面（HMI）系統的核心精神：**既要尊重人工操作的最高權威，又不能讓系統永遠卡在某個模式無法自我恢復**。

## 常見錯誤除錯站

| 現象 | 可能原因 | 解決方式 |
|---|---|---|
| 繼電器完全沒有反應 | IN 腳位接錯，或 VCC/GND 沒有正確供電 | 檢查繼電器模組三隻控制腳（VCC、GND、IN）是否正確接線 |
| PIR 感測器一直誤判為「持續有動作」 | 這是 PIR 感測器的正常特性之一，內部通常有一段「觸發後的穩定期」 | 屬於元件正常行為，可透過程式邏輯（如關卡 2 的延遲熄滅）妥善處理，不需視為錯誤 |
| 搖桿讀值中心點不是剛好 512 | 元件本身些微誤差，這是正常現象 | 可以把「無操作」的判斷範圍設定得寬鬆一些（如 400~600），而非嚴格要求剛好 512 |
| 手動模式永遠不會自動恢復 | `millis()` 計時邏輯寫錯，或忘記在偵測到操作時更新 `lastManualActionTime` | 檢查 `lastManualActionTime = millis();` 是否確實在偵測到搖桿動作時執行 |
| 模式切換後，RGB 燈號沒有跟著正確變化 | `setColor()` 呼叫位置放錯，或條件判斷邏輯寫反 | 檢查 `if (manualMode) {...} else {...}` 兩個分支內的顏色設定是否對應正確 |
| BOSS 關程式碼中，手動模式判斷邏輯完全沒有生效 | `joystickActive` 的判斷條件或門檻範圍設定不合理 | 檢查 `xValue < 400 \|\| xValue > 600` 這段邏輯是否正確反映搖桿中心點附近的合理容忍範圍 |

### 🔴 挑戰題
11. **多負載繼電器管理**：想像系統需要控制兩個獨立的負載（例如照明與風扇，需自行擴充第二顆繼電器接線），設計一個能分別用搖桿 X 軸與 Y 軸獨立控制兩個負載開關的系統。
12. **PIR 冷卻時間設計**：真實 PIR 感測器觸發後，通常需要一段「冷卻時間」才能再次準確偵測新的動作。請設計一個模擬冷卻機制：偵測到動作後，接下來 2 秒內即使 PIR 訊號改變也不重新觸發，避免過於頻繁的狀態切換。
13. **多模式狀態機重構**：把 BOSS 關程式碼中「自動/手動」兩種狀態，改用第 6 週提過的 `enum` 概念定義成 `OperationMode` 列舉型別（AUTO、MANUAL、TRANSITIONING 三種狀態），並設計「切換中」狀態的過渡邏輯（例如切換瞬間先閃爍提示 0.5 秒再正式切換）。
14. **搖桿死區（Deadzone）精確校正**：設計一個「搖桿校正」程序——開機時先讀取搖桿在「靜止不動」狀態下的實際中心值（而非假設剛好是 512），並以這個實測值為基準動態計算「無操作」的容忍範圍，讓系統更精準適應不同搖桿元件的個體差異。
15. **完全自訂控制台系統**：不參考任何範例，設計一個「你認為最完整的自動/手動控制台系統」，至少要用到：繼電器負載控制、PIR 或其他感測器的自動觸發邏輯、手動優先權設計、逾時自動恢復機制。

## 🔬 補充實驗室：繼電器的真實工業應用場景

繼電器雖然在這週的模擬電路裡只是控制一顆 LED，但在真實工廠環境中，繼電器（或其功率更大的親戚——電磁接觸器）幾乎無所不在。以下整理幾個常見的真實應用場景，幫助你把這週學到的概念與未來職場經驗連結起來：

| 應用場景 | 繼電器扮演的角色 |
|---|---|
| 產線馬達啟動器 | PLC 用低電壓訊號觸發繼電器，繼電器再接通馬達的三相高壓迴路 |
| 溫控系統加熱器 | 溫度控制器透過繼電器開關加熱線圈的大電流迴路 |
| 緊急停止迴路 | 安全繼電器確保只有在所有安全條件都滿足時，才允許主迴路通電 |
| 家用智慧插座 | 手機 App 送出的訊號經過 Wi-Fi 模組轉換成邏輯訊號，觸發繼電器切換插座通斷電 |
| 電梯控制系統 | 各樓層召喚訊號透過繼電器邏輯決定電梯運行方向與停靠樓層 |

**討論延伸**：這學期到目前為止，我們已經用軟體邏輯模擬過「警報鎖定與人工復歸」（第 6 週）、「安全連鎖」（第 7 週）、「手動優先權」（本週）——這些概念在真實工廠中，往往正是透過「繼電器邏輯電路」加上「PLC 程式邏輯」共同實現的。換句話說，你這學期學到的**程式邏輯思維**，即使換到完全不同的硬體平台（PLC 而非 Arduino），核心的設計精神依然完全適用。

## 📐 系統設計小練習：畫出你的優先權流程圖

在正式進入下週的期末整合大專題之前，這裡提供一個小小的暖身練習，訓練「先規劃、再動手」的工程習慣：

1. 拿出一張紙，畫出 BOSS 關程式碼的優先權判斷流程——用方塊代表每個判斷步驟，箭頭代表流程走向。
2. 標示出「搖桿是否有動作」這個判斷在整個流程圖中的位置，並想一想：如果這個判斷被移到流程圖的最後面才檢查，會發生什麼問題？
3. 試著在你的流程圖上，額外加入一個「緊急停止」判斷方塊，並放在你認為最合理的優先權位置，說明理由。

完成後，請與同組同學互相比較彼此畫出的流程圖，討論彼此優先權順序的安排是否合理，這個練習會直接幫助你在下週的期末大專題中，更有系統地規劃自己作品的優先權架構。

> 💬 小提醒：流程圖不需要畫得多精美，重點是「把腦中的邏輯順序具體畫出來」，這個習慣會讓你在下週面對更複雜的整合專題時，減少反覆修改程式碼的次數。

> 📝 延伸任務：如果時間允許，可以再試著為「主題卡 D」或「主題卡 E」的其中一個情境，各自畫一張優先權流程圖，比較不同情境下的優先權排序邏輯有何異同。
