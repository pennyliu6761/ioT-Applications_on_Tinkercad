# 附錄 B：常見錯誤排除手冊（給工管系初學者）

本附錄彙整全學期 16 週課程中最常見的錯誤類型，依「語法類」、「硬體類」、「邏輯類」、「進階架構類」四大分類整理，方便學生自行查閱排除，也方便教師快速定位學生問題的根源。

## 語法類錯誤

| 錯誤訊息／現象 | 常見原因 | 解決方式 |
|---|---|---|
| `expected ';' before ...` | 少打分號 | 檢查錯誤訊息指出的行數「上一行」是否忘記加 `;` |
| `expected declaration before '}'` | 大括號數量不匹配 | 檢查 `{` 與 `}` 是否成對，可利用程式編輯器的自動配對顏色提示 |
| `was not declared in this scope` | 變數名稱拼錯，或變數宣告在使用範圍之外 | 檢查變數名稱大小寫是否一致；確認變數宣告位置 |
| `'Servo' does not name a type` | 忘記 `#include <Servo.h>` | 檢查程式最上方是否有引入對應函式庫（第 7、11、12 週會用到） |
| `redefinition of ...` | 同一個變數或函式被宣告了兩次 | 檢查是否不小心複製貼上時重複宣告 |
| 浮點數運算結果永遠是 0 | 誤用整數除法（如 `5 / 1023` 而非 `5.0 / 1023.0`） | 第 6 週開始大量使用 `float`，務必記得數值後方加上 `.0` |

## 硬體類錯誤

| 現象 | 常見原因 | 解決方式 |
|---|---|---|
| LED 完全不亮 | 長短腳接反、忘記接 GND、腳位打錯 | 對照程式碼中的腳位變數，逐一核對實際接線 |
| 按鈕讀值一直跳動或恆為 HIGH | 忘記加下拉電阻，腳位處於「懸浮」狀態 | 確認下拉電阻確實接到 GND，且訊號線同時接到按鈕與電阻交界處 |
| `analogWrite()` 完全沒有調光效果 | 腳位沒有接在支援 PWM 的腳位上 | 確認接線在 `~3`、`~5`、`~6`、`~9`、`~10`、`~11` 這些標示 `~` 的腳位 |
| 伺服馬達不動或抖動 | 電源不足、忘記 `.attach()`、角度超出 0~180 範圍 | 檢查是否呼叫 `attach()`；用 `constrain()` 限制角度範圍 |
| LCD 顯示空白或全黑方塊 | 對比度未調整、接線腳位對應錯誤 | 確認 V0 腳位有接可變電阻調整對比度；核對 RS/E/D4-D7 接線順序 |
| `pulseIn()` 讀值永遠是 0 | Trig 與 Echo 接反，或忘記設定正確的 `pinMode` | 確認 Trig 是 `OUTPUT`，Echo 是 `INPUT` |
| L293D 接線後完全沒反應 | 兩組電源腳（Pin 8、16）或接地腳沒有全部接妥 | 逐一核對 L293D 十六隻腳位接線，這是最容易漏接的元件之一 |
| 位移暫存器完全沒有任何輸出反應 | MR（重置腳）沒有接 5V，或 OE（致能腳）沒有接 GND | 檢查 Pin 10 與 Pin 13 是否依指示正確接線 |
| 繼電器完全沒有反應 | IN 腳位接錯，或 VCC/GND 沒有正確供電 | 檢查繼電器模組三隻控制腳（VCC、GND、IN）是否正確接線 |
| 矩陣鍵盤按下沒有任何反應 | 8 隻接腳的行列順序接錯 | 逐一核對每隻腳位的行列對應關係 |

## 邏輯類錯誤

| 現象 | 常見原因 | 解決方式 |
|---|---|---|
| 按一下按鈕卻切換好幾次 | 按鍵彈跳（Bouncing） | 加入 `delay(50)` 簡易防彈跳，或使用狀態轉變偵測（`currentState == HIGH && lastState == LOW`） |
| 感測器數值忽大忽小很不穩定 | 感測器雜訊、模擬環境訊號誤差 | 可多次讀取取平均值；檢查判斷門檻是否留有足夠容忍空間 |
| 計數器不斷瘋狂累加 | 沒有使用「狀態轉變偵測」，而是持續判斷 | 檢查是否正確使用 `isXXX && !wasXXX` 的寫法（第 5、9、13 週反覆出現） |
| `if-else` 判斷結果與預期相反 | 誤用 `=`（賦值）而非 `==`（比較） | 檢查所有條件判斷式，`=` 是賦值、`==` 才是比較 |
| 警報永遠不會解除 / 永遠不會鎖定 | 忘記設計對應的觸發或解除條件 | 對照該週講義的警報鎖定範例，逐行核對邏輯 |
| `map()` 算出來的數字超出預期範圍 | 四個參數順序搞混 | 對照語法 `map(原始值, 原始最小, 原始最大, 目標最小, 目標最大)` 逐一核對 |
| `switch` 語句某個 case 沒有執行預期行為 | 忘記寫 `break;` 導致程式穿透到下一個 case | 檢查每個 case 是否都有 `break;`（第 14、16 週會用到） |

## 進階架構類錯誤（第 8、15、16 週大型專題常見）

| 現象 | 常見原因 | 解決方式 |
|---|---|---|
| 單獨測試沒問題，整合後卻出錯 | 多個子系統之間共用了同一個變數名稱，互相覆蓋 | 檢查每個子系統的變數命名是否清楚不重複 |
| 安全連鎖判斷部分失效 | 判斷式沒有放在 `loop()` 最前面，或忘記 `return` | 確認優先權判斷永遠是 `loop()` 的第一段邏輯 |
| 重構成 `millis()` 後，某個動作完全不會觸發 | 忘記在事件發生時記錄 `xxxTime = millis();` | 檢查每個非阻塞計時器，事件觸發瞬間是否有更新時間戳記變數 |
| 兩個 `millis()` 計時器互相干擾 | 誤用了同一個變數名稱記錄不同用途的時間 | 確認每組獨立計時邏輯，都有各自專屬、不重複的變數名稱 |
| 系統壓力測試時出現「卡死」現象 | 殘留某處忘記移除的長時間 `delay()` | 搜尋整份程式碼中所有 `delay()`，逐一確認是否都是必要且極短暫的 |

## 🩺 通用除錯心法（適用所有情境）

1. **先驗證硬體，再寫邏輯**：任何新元件接上後，先用最簡單的測試程式碼（如第 8、15 週示範的「硬體總體檢」）確認讀值/動作正常，再開始撰寫複雜邏輯。
2. **善用 Serial Monitor**：這是整學期最重要的除錯工具，隨時在關鍵節點印出變數數值，確認程式邏輯是否符合預期。
3. **二分法排查**：面對大型整合系統出錯時，暫時註解掉部分子系統的呼叫，逐步縮小問題範圍，而非對著整份程式碼漫無目的檢查。
4. **回頭查閱該週講義**：每週的「常見錯誤除錯站」都是針對當週新元件量身設計，優先查閱對應週次的除錯表。
